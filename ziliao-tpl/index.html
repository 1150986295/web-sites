01 施工规格书·修正版

资料库原件 ↗

AI 施工的总章程：两套模板规矩+巡检+第九章视觉工序

网页模板施工规格书（两套：单页站 / 多页应用）· 修正版

读者：执行施工的 AI（WorkBuddy） 用法：整份发给 AI，先按「〇 总要求」开工，再按「二 / 三」分模板施工 核心原则：模板不是"更好看的页面"，是"把已知的坑提前做进骨架里"

⚠ 实测值声明（2026-11-25 增补）：本方案所有具体数字（长边 1080、红点 50 条上限、对比度 4.5/实测 11.4~12.4、断连阈值、分页 20 等）均为 2026-11 WorkBuddy 平台三个项目的实测值。换平台、换托管、换流量规模时必须重测再改写，禁止照抄——经验库的价值是"踩坑的方法与顺序"，不是数字本身。

修正记录（2026-11-25，以模板 A/B 实际施工与巡检验收为准）： ① §1.5 压缩参数统一为长边 1080（原 1600，与模板 B 实测实现不一致）； ② §2.2 "微信分享卡片"降级为可选（纯静态单文件拿不到微信 JS-SDK 签名，做不到缩略图，硬性要求会误导验收）； ③ §1.3 红点补充：localStorage 键名必须按站独立命名（如 zx_errlog_v1 / jm_errlog_v1），防止多站互相污染； ④ §1.7 巡检更新：工具已支持 fill/check/run/upload 动作、深色模式模拟、对比度计算（现实测 11.4~12.4:1）； ⑤ §七 省钱纪律修正：数据正确性/权限类施工不许用最低档模型（实测 Flash 档会产出"看着对其实错"的代码），只有纯机械贴码用 Flash。

〇 给 AI 的总要求（先读这一节）

0.1 一句话

我要的不是两个成品网站，是两个可以复制、改文案换图就能交付的骨架。判断做得好不好，标准只有一个：下一个新站复制它，能不能不返工就上线。

0.2 五条不可协商

  1. 不许一次做完。 按本文档的"阶段"分批交付，每阶段我验收通过才进下一阶段。一次做完必炸。
  2. 不许自行发布上线。 每阶段做完给我预览，我确认后才进正式。
  3. 不许顺手优化。 我列的范围之外一律不动；改完必须汇报"改了哪几个文件、每个改了什么、没动哪些"。
  4. 验收只认证据：手机打开看见 + 截图 / 巡检产物文件。你说的"已完成 / 测试通过"一律不算。
  5. 删除任何东西前，先答影响面四问（谁在读 / 谁会静默失败 / 能否先加后删 / 怎么证明没人用），答不出不许删。

0.3 两套模板的关系

模板 A · 单页站 模板 B · 多页应用
用途 活动页、请柬、门店介绍、工具页 报名投稿、打卡、带后台的系统（墨缘级）
依赖 纯静态，无后端 身份 + 数据库 + 后台接口
施工量 1–2 轮 6–8 轮，分 5 阶段
复制成本 改文案换图，20 分钟上线 改表结构 + 品牌，1–2 天

先做 A，再做 B。 A 是 B 的地基（骨架、令牌、三态、红点、巡检都在 A 里先跑通）。

一、两套模板共用部分（必须先做，B 会直接复用）

1.1 设计令牌（一个文件管全站）

:root 里定义：主色 / 强调色 / 底色 / 文字三级 / 字号 5 档 / 间距 4 档 / 圆角 2 档 / 阴影 2 档
规则：组件只引用变量，全文件禁止出现裸色值（除 :root）
要求：改一个 --color-primary，全站主色同时变
  • 强调色全站只有 1 个，专给主操作；标签、装饰不许抢
  • 正文 ≥16px，辅助 ≥13px，行高 1.75
  • 涉及书法的站，笔类文案统一写「毛笔 / 硬笔」，不写「软笔」

1.2 六态（比三态多三个，这是大项目的安全网）

态 触发 必须给什么
加载 请求发出后 骨架屏或明确"正在加载"，>1 秒必须有反馈
空 请求成功但无数据 一句"这里该有什么" + 一个下一步按钮
错误 请求失败 三段式：发生了什么 + 为什么 + 现在怎么办（带重试）
未登录 无 token 引导登录，不要白屏
无权限 403 说明"你没有这个权限"，绝不清空登录态
成功 操作完成 明确的成功反馈 + 下一步（别只 toast 一句"成功"）

禁止文案："请稍后重试""操作失败""网络异常"。必须写具体原因和下一步。

1.3 前端错误记录（红点）

  • 监听 window.onerror + unhandledrejection，把「时间 / 页面 / 错误信息 / 前 3 行调用栈」写进 localStorage 环形缓冲（最多 50 条）
  • 红点键名按站独立命名（如 zx_errlog_v1 / jm_errlog_v1），多站共用一个键会互相污染历史记录
  • 页面角落显示一个小红点：有未读错误时亮，点开能看到错误码
  • 用途：用户截图来报，或我自己打开就看见，不再"听别人说才知道坏了"
  • 验收判据：断网提交一次 → 刷新 → 红点还在

1.4 首屏与切场

  • 入口 HTML 自带底色（body{background:...}），遮罩先于内容挂载——不许冷启动白屏
  • 切页统一走一套引擎：只动 opacity/transform，播一次即固化（幂等标记），禁止用 display/height/width 做动画，禁止刷新重复播

1.5 图片与体积

  • 上传前 canvas 压缩：长边 ≤1080px、转 JPEG 质量 80、单张 <1MB（模板 B 实测：2000×1500 的 73KB 图 → 1080×810 的 14KB）
  • 列表用缩略图 + loading="lazy" + decoding="async"；详情/下载用原图
  • 提交前估算总量，>25MB 拦下并提示"图片过大，请减少张数"
  • 错误提示必须区分"体积过大"和"网络异常"
  • 图片只用站内相对路径（assets/…），不许外部短链

1.6 移动端四条硬规矩

  1. input.files 是 live FileList：先 Array.from() 拷贝，再 value=''
  2. 弹层/面板高度要扣掉底部导航，"保存/提交"必须在可视区内
  3. 装饰层（水印、悬浮球）z-index 低于可点元素
  4. touch-action 用 pan-y，不要 none

1.7 巡检配置（每个新站一份）

  • 一个 巡检配置.json：填 url + 关键动作（点哪 → 截图；已支持 click/goto/wait/fill/check/run/upload，可断言状态、可填表单、可测文件上传）
  • 固定检查项：HTTP 状态 / 标题 / 入口底色 / console 报错 / 资源 4xx / 横向溢出 / 禁词扫描 / 红点历史 / 动作回放截图 / 对比度计算（≥4.5:1） / 可选深色模式与"减弱动效"模拟
  • 产物落目录（PNG + results.json + index.md 的 FAIL 表），AI 转述的"X 项过"不算
  • 结论表述规范：每条 PASS 标明覆盖范围（如"首屏 PASS"），不许把动作回放范围写成"全站全 PASS"
  • 排查纪律：FAIL 连锁出现时，先看链条第一环是巡检时序（动作比切场快，加等待重跑）还是真 bug

1.8 交付物（每个模板都必须带）

index.html（或入口文件）
assets/（图片、字体；字体必须可商用）
README_使用说明.md（怎么改字、怎么换图、怎么上线、出问题找谁）
HANDOVER.md（项目结构 + 红线 + 当前状态）
巡检配置.json

二、模板 A · 单页站（第一阶段，1–2 轮）

2.1 目标与结构

  • 一个文件优先：index.html（内联 CSS/JS）+ assets/。理由：单文件复制最不容易出错，无构建依赖、无路径问题
  • 一个页面，五个区块：头部（标题/副标题/二维码位）→ 主视觉（图/视频）→ 信息区（时间地点/流程/介绍）→ 行动区（报名/加微信/导航）→ 页脚
  • 只做三类动作：看信息、点按钮跳转、长按/保存图片

2.2 必须内置

  • 设计令牌 + 六态（简化为三态：加载/错误/空）
  • 首屏底色 + 一张主图的渐进加载（先底色，再淡入，避免白屏）
  • 全部内容手机 375px 可读：无横向滚动、无文字溢出、英文整词换行
  • 底部固定行动按钮（一个，不重复）
  • 分享卡片（可选）：设置 title 与 meta 描述即可；微信转发缩略图需公众号 JS-SDK 签名，纯静态单文件做不到，不作硬性验收项
  • 红点 + 巡检配置

2.3 禁止

  • 不加登录、不加后台、不加数据库、不做表单自建收集（表单走第三方跳转）
  • 不引入任何需要联网加载的第三方库（离线打不开就是坏的）

2.4 验收（逐条打勾才交付）

□ 手机 4G 打开，3 秒内看见内容，无白屏
□ 375 / 390 宽无横向滚动，无文字溢出
□ 每个按钮点得到，在可视区内
□ 断网：显示错误态而不是空白
□ 主图加载前有底色，加载失败有占位
□ 改一个令牌颜色，全站同步变
□ 巡检跑一次，首屏 PASS，无 console 报错
□ README 能让一个没看过这个项目的人独立改文案换图

2.5 复制出新站的做法（写进 README）

1. 复制整个文件夹，改名项目
2. 改 :root 里 3 个颜色（主色/强调色/底色）
3. 换 assets 里的图和文字
4. 改 title 和分享卡片信息
5. 上传托管 → 手机验收 → 结束

三、模板 B · 多页应用（墨缘级，第二阶段，5 阶段 6–8 轮）

3.1 开工前必须先定三件事（我拍板，你记录）

决策 选项 影响
身份从哪来 平台身份 / 自建账号 决定能不能搬走，选了平台就不可移植
数据存哪 平台数据库 / 自建（Supabase 类） 决定备份方式和迁移成本
谁在用什么 学生看作品 / 管理员审作品 / 都要 决定权限模型复杂度

这三条没定，不许开工。 定了写进 HANDOVER.md 的决策记录：选了什么、代价是什么、什么情况下重审。

3.2 阶段 1 · 骨架（最容易偷懒、也最致命）

  • 单入口 + 路由表：所有页面在路由表里登记，路由表是唯一来源
  • 目的：杜绝"两个按钮跳同一页""入口和页面对不上"
  • 每个入口都要能在路由表里查到；加页必须先加路由表
  • 切场引擎：统一一套入场/退场，只动 opacity/transform，200ms 退场
  • 布局壳：顶部安全区 + 内容区 + 底部 tab；内容区高度必须扣掉底部 tab
  • 装饰层：水印/悬浮球统一放在低于交互层的层级

阶段门（不过不许进下一阶段）：

□ 每个 tab 都跳到它该去的页面（逐个点验，记下"tab → 页面"对照）
□ 切页有过渡，无闪断、无重复播
□ 底部按钮全部可点，无被遮挡
□ 手机 375 宽无溢出

3.3 阶段 2 · 身份与权限（P0 高发区）

  • 身份只有一个源：登录返回 {token, who}，绝不并存 isAdmin 这类第二身份源
  • 双键成对：token + who 一起写、一起清；401 清空整套，403 绝不清空
  • 双层守卫：前端藏入口（display:none）+ 后端每个 /api/admin/* 独立校验 token
  • 只做一层都会被绕过
  • 身份数据只存一张表：不许"登录查 A 表、改密写 B 表"（会导致改密永远失败）
  • 姓名等不可信字段从 token 取，不许前端传（前端传等于可伪造）
  • 首登改密必须能走通，不能把人锁死在"必须改密"里

阶段门：

□ 未登录点后台入口 → 引导登录，不白屏
□ 登录后访问无权限接口 → 403 提示，但仍是登录状态（不强制登出）
□ token 失效 → 401 → 清空并回登录页
□ 连续刷新 5 次、进出后台 3 次，不掉登录
□ 首登改密走通，改完能用新密码登录
□ 管理员和学生在同一接口下看到的数据范围正确

3.4 阶段 3 · 数据与接口

  • 接口统一返回 {code, message, traceId}；生产环境绝不返回 SQL、堆栈、表结构
  • 缺参返回 400 + 中文提示，不许 500
  • 列表接口分页（默认 20/页），排序稳定
  • 时间、状态、编号都用固定格式，全站统一
  • 备份：一键导出 JSON（全表）+ 导入校验；每次结构变更前先导出
  • 写操作要有幂等：重复提交不产生两条数据（按钮防连点 + 后端去重）

阶段门：

□ 增删改查各跑通一遍，刷新后数据还在
□ 故意不传参数 → 返回 400 + 中文提示
□ 故意触发异常 → 返回 code/message，看不到 SQL
□ 连点提交 3 次 → 只产生 1 条数据
□ 导出 JSON → 删一条测试数据 → 导入 → 数据还原

3.5 阶段 4 · 上传与后台

  • 上传：压缩 → 进度 → 失败可重试；不允许"上传中点了没反应"
  • 后台列表：分页 + 筛选 + 批量操作，批量删除要二次确认
  • 后台每个操作要能看到结果（成功提示 + 列表变化）
  • 删除是软删除（可恢复），或删除前自动导出备份
  • 后台操作记录：谁、什么时候、改了什么（一行一条）

阶段门：

□ 传 4 张大图（每张 5MB 级）→ 成功，无断连，有压缩
□ 传 1 张 30MB 图 → 明确提示"体积过大"，不是"网络异常"
□ 上传中切后台再回来 → 状态正确，不重复提交
□ 批量删除 → 有二次确认 → 删完列表刷新正确

3.6 阶段 5 · 动效与打磨

  • 统一引擎（骨架阶段已内建，这里只做调优）：入场级联延迟、退场 200ms、回弹曲线
  • 进度口径唯一：同一屏只允许一个分母，且分母由数据算出来，不许写死
  • 角色/图标朝向由单一变量控制，左右都要验
  • 弱光可读：对比度 ≥4.5:1，可点区域 ≥24×24px

阶段门：

□ 同一屏所有进度数字分母一致，且与真实数据条数相符
□ 空数据时显示空态，不是"0/0 完成"
□ 弱光下正文能看清，按钮点得到

八、脱平台与可移植性（发布前必查）

背景：我们的站都跑在 WorkBuddy 平台托管上（*.app.workbuddy.host + sharecode 链接）。模板要保证：哪天要搬走，随时能搬。

8.1 可移植性四查（每个新站交付前过一遍）

□ 零外部依赖：不引用任何需联网才能加载的第三方库（模板 A/B 均为单文件零依赖）
□ 无平台注入残留：页面 JS 里搜平台注入物（如平台 boot 脚本、统计脚本），列入红线不许依赖
□ 无平台专有接口：数据层不依赖平台私有 API——模板 B 的所有数据走 mock() 一层，换后端只改这一处
□ 路径全相对：assets 引用全部相对路径，拖到任何静态托管直接打开

8.2 mock 替换表（模板 B 换真实后端的施工地图）

模板 B 全部接口收敛在一个 mock() 函数里（这是设计，不是偷懒）。换后端 = 只改这一层：

mock 接口名 换后端时
register / login / changePwd 换成真实身份接口，返回体形状不变 {code,message,traceId,data}
addItem / list 换真实增查接口，分页形状不变 {list,total}
exportAll / importAll 换真实备份接口；导出脱敏规矩不变
deleteItems / getLogs / adminStat 换真实管理接口，401/403 语义不变

替换纪律：一次只换一个接口 → 跑巡检 → PASS 再换下一个。页面代码零改动。

  • 域名归属：给客户/社团做站，正式域名必须落在对方名下（备案主体写对方），平台托管只作过渡——防止"站在我账号上，人走了站没了"

九、视觉施工工序（每站标配，骨架验收后必做）

定位：骨架=毛坯房，视觉施工=装修。跳过这轮，站就是"能用但难看"——演练站（兰亭招新页）已验证：只改3色交付必然难看，此工序必须列为标配。

9.1 范围纪律（写死）

  • 只许动 CSS 和 HTML 展示层（配色层次、卡片质感、字体排印、间距节奏、头图区、插画/纹样装饰）
  • JS 逻辑零改动：mock()、goto()、WHO、401/403、红点、上传、备份、幂等、确认词，一个字不碰
  • :root 三色可调但不许加第二个强调色（强调色全站唯一，专给主操作+红点）

9.2 流程（五步）

① 定母题：按站型定调性（活动页热闹 / 系统站素雅 / 书法类纸墨调）
② 扩令牌：新颜色一律定义进 :root，组件禁写裸色值
③ 改展示层：头图区、卡片质感、字体排印（系统字体栈，不外链字体文件）、留白宁大勿挤
④ 每站一个记忆点：强制想一个"别人没有的小东西"（墨缘的每日名言行书、竞墨的强制登记都是这么来的）
⑤ 验收：浅色+深色巡检全 PASS + 对比度≥4.5 + 三页截图（首页/列表/关键页）给用户看

9.3 模型与轮次

  • 视觉调优是"改一步看一步"的判断型工作：用口碑档（GLM-5.3），不用 Flash 档（会调出"技术正确但呆板"的效果）
  • 1–2 轮；每轮验收只认截图+巡检，不认"已美化"

9.4 图标与美术规范（大厂惯例，写死——兰亭招新演练站视觉施工验证）

  • 图标一律内联 SVG 线性风格：24 viewBox、stroke-width 1.7、圆头圆角（round cap/join）、stroke="currentColor" 随文字变色、底栏图标统一 22px 网格。禁止 emoji 当图标——设备字体差异大（部分机型显示方框）、风格不可控
  • 母题先行：动 CSS 前先写一句母题（如"宣纸 × 墨 × 朱砂"），之后每个颜色决定回溯这句
  • 深色不是变灰蓝：深色必须延续同一母题重调色相（纸墨调 → 暖墨底 + 宣纸字 + 提亮朱砂 + 淡金主色），禁止简单把亮色变暗了事
  • 强调色的唯一豁口：除主操作与红点外，全站只允许一处"品牌印记"用强调色（如顶栏朱砂小印），其余装饰一律禁用强调色
  • 质感用纸纹不用重投影：细描边 + 双层淡阴影 + 细纹理线；禁 heavy box-shadow
  • 字体不外链：标题楷体/衬线系统栈，正文无衬线系统栈；对比度浅深两套实测 ≥4.5

第一部分 · 三个项目分别踩的坑

一、墨缘（豆包平台 · 大项目 · 带后台的多页 Web App）

性质：书画协会作品征集平台，20 天工期，多页面 + 完整后台 + 身份认证 + 数据库。发布在豆包/秒哒平台。

发布与判据（最惨痛的一类）

• "构建成功"不等于"发上去了"。 唯一判据是 CDN 目录名 = commit 完整 hash，hash 没变就是没发布。曾靠"构建成功"提示误判多次。 • 发布前先弄清这次会带上哪些 commit——rebase 曾一次带进 7 个主分支提交，自己却只知道"修了什么"。 • 主分支禁止 force push；特性分支 rebase 后用 --force-with-lease，不用 --force。 • 靠主包字节数 + md5 差异判断"这版到底改没改前端"——字节数完全相同、md5 只差几处，说明前端零实质改动，全在后端。

2026-11-09 全站打不开事故：删了一个"看起来没用"的请求头

这就是"改功能 → 发现要补功能 → 页面打不开"那次。用户记忆模糊，这里记全，因为它是最阴的一类故障——静默失败。

• 起因：为了修一个 bug，删掉了请求头 x-larkgw-suda-*。它"看起来没用"——删完代码不报错、构建成功、资源全返回 200。 • 真相：平台靠这个头注入 appId。头没了 → 入口 HTML 注入出 appId="" → 前端判定"应用不存在"，全站打不开。 • 最阴的地方（分层验证的教训）：当时 L0 传输层全是 200（CLI 显示 finished、JS/CSS 都能下载），但 L2 渲染层是"页面不存在"、L3 运行时 appId=""。只看"资源 200"会得出"是好的"这种完全错误的结论。 • 事故前的原话信号："这个应该不影响别的功能"——后来这句话被列进"听到就立刻叫停"清单。 • 处置教训：先回退后查因。当时先分析再回退，用户在外面干等很久。

由此立下两条通用规矩（已沉淀到发版约束卡）：

  1. 影响面四问（删除/重命名任何请求头、字段、环境变量、路由、策略前必答）：
  2. 除了我，还有谁在读它？（平台注入层、框架、其他模块、外部脚本都算）
  3. 删掉它，谁会静默失败——不报错、但行为变了？
  4. 能不能先加后删（分两步）？
  5. 我怎么在 5 分钟内证明没人用？（全仓搜引用 + 查平台行为 + 测试环境单独删一次观察，三者缺一视为未证明）
  6. "不报错"不等于"没人用"——这是静默失败最贵的地方。以及发版后分层验证：L0 传输→L1 文档→L2 渲染→L3 运行时→L4 业务，必须"浏览器打开亲眼看见内容+截图"，状态码不算数。

认证与权限（技术债高发区）

• 401 和 403 必须区别对待：401 → 清空 localStorage 并强制登出；403 → 不清空。曾因 badges?studentId= 带合法 token 仍返回 401，导致"登录后点我的被强制登出"的 P0。 • suda-csrf-token cookie 只防跨站，不是身份凭证；光有 cookie 不算登录，必须带 Bearer token。 • 别"顺手写成统一守卫"：badges 接口兼着匿名公开的徽章墙，手写校验是有意为之，套硬守卫会把匿名请求也打成 401。 • 删字段要治本：让后端从 token 取 studentName，而不是前端补字段——前端补等于让客户端可伪造姓名。

身份失效循环 + 管理员/学生身份名单混乱（最大的 P0 区）

这是墨缘最纠缠的一类坑：一个"鉴权小改动"能引发"所有人一操作就被强制登出"的连环故障，且管理员和学生各有不同的触发原因。

• 别让 401 和 403 一起触发"身份失效"：旧代码写的是 status !== 401 && status !== 403 就广播 auth-lost——结果任何 403 都清空登录态、弹"身份失效，请重新登录"。而登录成功时会重置一次性标志位，导致每次重新登录后遇到的第一个 403 又触发一次，形成可重复、不自愈的死循环。修法：只认 401，403 绝不登出。 • "被强制登出"要分清环境再动手：用户报"所有账号一操作就掉线"，实测正式地址登录、进 4 个后台 tab、首页↔作品往返，全程 0 个 401/403——问题在豆包对话框预览（构建 dev）和正式版不是一套登录环境。先问"测的是哪个环境、版本号对不对"，别急着改代码。第一优先是分清环境，不是派活排查。 • 一个字段两套表，改密必失败：admins 和 class_students 双表密码哈希不同步——登录查一张、改密写另一张，导致改密码返回 403"当前密码不正确"，但同一个密码却能登录。身份数据绝不能散在两张表里。 • 身份判断别用前端硬编码/双身份源：曾出现"已登录已加入仍显示『我要加入』"（按钮无条件渲染、没套状态判断）；还有 localStorage 只有学生 token 没有管理员 token、靠 cookie 会话撑着的历史悬案。身份以服务端为准，前端只做展示。 • 名单/权限的错，很多是"前端多套了一层 isAdmin"：接口本就返回全量名单，前端却套 isAdmin 让普通会员看不到打卡名单；"学生管理页只剩删除"是操作列渲染被删减。先查接口返回，再看前端是不是自己把数据藏了。 • 两个入口跳同一个页面："开始打卡"和"硬笔书法"都跳 /hard-pen，是三元表达式第一个分支写错。这类"页面与入口不对应"要逐个入口点验，不能只看页面在不在。

判读规则（被坑两次，写死成规则）

• 自检报 error ≠ 系统故障：后台那 12 项红黄灯反映的是数据完整度，是一份"运营待办清单"，不是 bug 列表。代码错的标志是接口 500 / 白屏 / 点了没反应 / 数据串位；人没填的标志是列表能打开、字段空着。 • 别把"最近才注意到"当"最近才加的"：扣子测评称"这版刚加了备份/自检"，据此推出 P0——前提是假的（建站起就有），前提假 → 后面再精确的观测因果链也是断的。 • 报 404 先怀疑自己的路径：曾把 /api/calligraphy/all-works 记成 /api/all-works，误以为路由被删。前端 bundle 里能 grep 出全部真实路径。 • 实测反证，不要"补功能"：曾以为作品墙缺收藏按钮，实测 lucide-star=0 证明本来就没有（收藏只在详情页），补了等于新增功能、引入风险。 • "为修一个 bug 在生产开一个新口子"：为了让登录 500 的错误原文显示出来，给异常过滤器加了 rawMessage，结果把整条 SQL 和表结构返回给了前端——调试代码上了生产。教训：生产只返回 {code,message,traceId}，SQL 原文只写服务端日志，开发/预览环境才保留详细错误。 • 接口缺参别返回 500：多个接口不传参数直接 500 还吐 SQL，应在入口做必填校验、返回 400 + 中文提示。

性能与图片

• CDN 图片压缩参数必须编码形式：?x-tos-process=image%2Fresize%2Cw_800，裸写 image/resize,w_800 慢一倍。 • 列表用缩略图 + loading="lazy" + decoding="async"，详情页/放大/下载继续用原图。实测 455→88KB（-81%），加载 1.0-1.8s→0.3-0.4s。 • 等比缩放，不动 quality。

白屏、闪屏与"点了没反应"（前端交互层的高频坑）

• 冷启动白屏 2.17s（4G）/ 4.25s（3G）：四条根因——①入口 HTML 是空壳（只有一个 <div id="root">，0 个 style）；②遮罩和首页同帧挂载，没起到"先盖住"的作用；③云层与底色色差仅 11 阶，数学上有云、肉眼看不见；④sessionStorage 记忆导致刷新不播动画。压缩后仍有 0.86s。教训：入口 HTML 要有底色、遮罩要先于内容挂载。 • "选完图零请求、零报错、连占位都没有"：根因是 input.files 是 live FileList，e.target.value='' 会把它清空，而代码存的是同一个引用，紧接着 length===0 成立直接 return。同一个 bug 在三个入口复制了三遍。修法：先 Array.from(e.target.files) 拷贝再清空。对比定位的关键："更换封面"是好的，因为它取的是单个 File 对象、不受 value 清空影响。 • "保存点不到，其实命中底部 tab"：编辑面板高度没扣掉底部导航，按钮落在可视区外（y=843、屏高844、底栏56）。移动端弹层/面板要算上底部 tab 高度。 • 装饰层 z-index 高于交互层："我的"页按钮被水印遮挡；右侧悬浮球重复渲染遮挡内容。装饰永远不能盖住可点元素。 • "点确认删除"弹窗关了但零请求：只关了弹窗、没调删除接口，刷新还在。关窗≠执行，要验后端数据真的变了。 • 自动化脚本命中不可见按钮导致误判："改图保存不生效"是脚本用了"页面上最后一个含『保存』的按钮"，命中的是隐藏候选元素；"共X张"读的是编辑区文案不是列表长度。脚本误判要复测推翻，别据此写根因（这条最后撤回留档）。 • 58 个元素带 touch-action:none → 后台成员列表手指起滑无反应，只能在信息框外滑。应改 pan-y。移动端别乱禁触摸。

验收视角

• 别用 admin 视图验视觉效果：admin 默认在"编辑态"，看到的是平铺管理列表；要关掉右上角编辑开关切到"浏览态"才是用户看到的 3D 轮播。曾因此误判"功能没上线"。

成本（豆包按 token 计费的特殊教训）

• 同类改动合并发：三处"加一个 URL 参数"分三次发，烧了 285 积分，代码各 1 行——贵在每次新任务都要重读整个代码库。合并发能压到个位数。 • 按输出量选模型，不按任务类型选：纯样式/CSS → 最便宜的 Flash；改逻辑/状态/接口 → 主力模型；判影响面/长上下文 → 贵模型。 • 验收交给本地巡检脚本（如 /workspace/tools/墨缘巡检.py），别让 AI 自己 build + 截图，每轮多烧一次。 • 省积分提示词反而费积分："让模型自己找最省办法"是反效果（它会花推理去想怎么省）。要用明确的短指令：不展示推理、严格按清单改、验证只做列出的项、卡住就停。

二、竞墨（WorkBuddy 平台 · 大项目 · 单文件 HTML + 后台接口）

性质：书法比赛征集系统，报名→投稿→后台评分→上墙→导出全链路。单文件 HTML 前端 + 后台接口，平台内已有真实数据（65 报名 / 63 交卷），测试时严禁碰 clearall / reset / remove。

最大的坑：骨架先天不是墨缘那种 → 切页像"划照片"（花大力气才补回来）

这是竞墨排第一的教训，比大图上传还根本——因为它决定了整个项目的"手感上限"。

  1. 起因：竞墨一开始的骨架就不是墨缘（豆包多页 App）那种带原生页面切换架构的形态，而是单文件 HTML。结果就是页面切换没有过渡，像划照片一样生硬——点一下 tab，整屏内容直接跳过来，没有墨缘那种丝滑切场。用户当时的原话诉求："它后面可以像墨缘一样拥有丝滑的切场动效吗？"
  2. 代价：这个"手感"是骨架层决定的，不是后期加个 CSS 动画能糊弄过去的。后来专门做了一套"统一入场引擎"才补回来：所有切页走同一套、只动 opacity/transform、幂等固化、级联延迟、回弹曲线、200ms 退场——等于在大项目后期回头补地基。
  3. 残酷的对比结论：因为骨架不同，竞墨在这项上对比墨缘天生没有优势，补救能做到"不生硬"，但要完全达到墨缘那种原生丝滑，成本很高。架构选型的债，最后是体验来还。
  4. 教训（写进通用规律）：切场/导航/动效这类"全局手感机制"，必须在骨架阶段就定死。不要想着"先能用，动效以后再说"——后期补是补不回原生手感的，而且会牵动所有页面。

鉴权设计（做对了的部分，可作为范本）

  1. 身份字段只定一个：登录返回 {token, who, recovered}，身份只有 who，绝不并存 isAdmin 这种第二身份源（两个源必然不同步）。
  2. localStorage 双键成对：lt_admin（令牌）+ lt_who（身份），注释写明"成对写、成对清；401 统一清空整套"。
  3. 前端藏 tab + 后端守卫双保险：未登录时管理入口 display:none，同时每个 /api/admin/* 独立检查 token——只做一层都会被绕过。
  4. 首登改密不死锁：识别组织者 → 自动弹初始密码改密框；但 needChange=true 的账号只 toast 不自动弹（遗留差距）。
  5. 学生登记 ≠ 登录：登记是姓名+学号+班级+手机+口令，设备指纹一机一次；登录是另一套。别混。

P0：大图多张上传必炸（最有价值的一条）

  1. 请求体 ≥ 约 38MB 时代理层直接断连（500 ECONNRESET）。手机照片 3~8MB，一次传 4 张大图就超，而前端只显示"网络异常，请检查网络后重试"——学生重试一百次也不会成功，现场会失控。
  2. 修法：上传前 canvas 压缩（长边 >1600px 等比缩到 1600px，转 JPEG 质量 80，单张压到 1MB 内）；提交前估算 base64 总量，>25MB 就拦下并提示"图片过大，请减少张数"；错误提示要区分"体积过大"和"网络异常"。
  3. 7.8MB 原图 → 8KB 缩略图（-99.9%），上传速度和成功率都翻倍。
  4. 并发退化：60 并发刷墙，60/60 成功但中位 4.6s、P95 5.3s（单发只要 0.1~0.5s）。压缩后单请求变小会明显缓解；流程上分组上传避免集体齐发。

动效（先天不足后的补救方案，思路可跨项目复用）

  1. 统一入场引擎（就是上面"划照片"坑的补救）：所有页面切换走同一套，只许 opacity/transform，播一次即固化（ENTER_SEEN 幂等标记）；用 getAnimations() 检测复播；禁止用 display/height/top/width 做动画。记住这是"亡羊补牢"——新项目应该在骨架阶段就把它内建进去，而不是事后补。
  2. 角色动画的朝向要统一由一个变量控制（如 scaleX(--dir)），左右方向都要验。曾出现"身体朝前、方向朝后跳"的怪异画面，就是因为朝向散落在多处。

测试纪律

  1. 压测后必须还原数据：测试作品/报名走正常删除通道清掉，复核真实数据原样（65/63、报名恢复 N 人、作品墙归零）。
  2. 危险操作要二次确认：删除报名需管理密码，clearall 需输入 CLEAR——测试时绝不碰。
  3. 声称的限流要实测：/api/recover 号称"5 次/分钟"，实测 20 次无 429 → 限流根本没生效。不要信注释里的数字。

三、专升本每日修炼（WorkBuddy 平台 · 小项目 · 纯单文件 HTML + localStorage）

性质：个人刷题备考站，5 页（今日/练习/知识/错题/我的），无后台、无账号、localStorage 存全部数据，只私发一两人用。

定位决策（小项目的核心是"克制"）

  1. 不要为了一两个人上名单登录/后台：那是把"能直接发的链接"升级成"要长期维护的系统"。而且挡不住转发——对方把链接往群里一丢照样进。私发链接 + 叮嘱即可。想留底就给每人发带不同随机参数的链接，外流了能知道从谁那儿出去。
  2. 数据只存 localStorage 是真实风险：清缓存或换手机 = 全部记录没了。对小项目，加一层导出/导入 JSON 就够了（几行代码），不要上云端同步（要账号后台，与"一两人私用"冲突）。
  3. 单文件 HTML 也能做复杂功能：记忆引擎（SM-2 简化：1→2→4→7→15→30 天，答错重置，按考点聚类错题）、计划引擎（以日期字符串为种子，同日刷新计划不变）都能纯前端实现。

一个页一个坑 → 立"总纲"（本项目最大教训）

  1. 视觉/排版没有总纲，就会"做一个改一个"：科目标签颜色反复改（实心绿太跳→朱砂撞按钮→蓝绿太像→最终黛蓝/紫檀/赭黄）；红字用 nowrap 撑出屏幕；字号 12~14px 费眼；公式是裸 LaTeX 源码 $\frac{}{}$。
  2. 根治：写一份 R3.8 全站排版总纲，优先级高于所有零散补丁，任何新页面动手前先过总纲（设计令牌、容器换行、通用组件、公式渲染、字号层级、自检清单）。
  3. 强调色只能有一个：朱砂红是全站唯一最高强调色，专留给"提交答案"这类主操作。科目标签也用朱砂，会稀释按钮、还带出"错误/警告"歧义。配色要在色环上拉开色相（蓝绿只差 60° 小标签上就糊成一类）。
  4. 字号别低于 16px 正文：手机上要逐字读的页面，12~14px 最费眼。辅助标签 ≥13px，行高 1.75。
  5. 英文单词断词：中文断行规则套到英文上会把 abstract 拆成 ab+stract。每个单词用 <span style="display:inline-block;white-space:nowrap"> 包起来，作为整词换行。
  6. 公式必须有渲染层：题库里是 LaTeX，必须有 KaTeX 渲染 + 离线降级（断网转 Unicode 符号），不能当纯文本输出。
  7. 跳转放最后：知识卡先讲透知识（定义→公式→题型识别→步骤→易错→例题），"相关题目 N 道"的跳转永远在最后一行，不得占主视觉。

交互与数据口径

  1. "翻面"和"跳题"不能糊成一个动作：用户想翻面看要点，却被送去做题——两个动作必须分开。
  2. 进度口径必须唯一：曾同屏出现"0/21 今日总进度""完成 1/3 组""已完成 0 段""0/4 段完成"四个数字三个分母，用户不知道信哪个。只保留一个分母，其余全删。
  3. 倒计时日期要持久化：刷新后变"距考试 -- 天"，因为日期没存 localStorage / 首屏读取时机错。存本地 + 同步读取 + 解析失败给默认值，不许裸 --。
  4. 同一屏数据不能自相矛盾：上写"到期复习 0 项"下写"14 项"、上写"新考点 0 个"下列了 3 个——两处组件各读各的数据源。统一取数。
  5. 脏数据会毁可信度：解析里写"故选 C"但题目根本没有选项；参考答案写成"the; /"。题库内容要单独核验，不能只验功能。

第二部分 · 通用经验（提炼成可执行的规律）

A. 开工前

  • 先写一页纸：谁用、每周来干的一件事、第一版必须有、第一版不要、三个月后只剩一个功能留哪个。写不出来就别开工——交给 AI 只会得到"什么都有、什么都不顺"。
  • 先定体量：小项目（个人用/一两人）走单文件 + localStorage，不上后台不上登录；大项目（多人/要数据/要权限）才上后台 + 鉴权 + 数据库。体量选错，后面全是白干。

B. 骨架与鉴权

  • 五阶段不跳：骨架 → 地基 → 内容 → 美化 → 试用。地基（权限、备份、错误提示、版本号）不产生界面变化，最容易被跳过，也最容易三个月后炸。
  • 骨架阶段就要定死"全局手感机制"——页面切换/导航/动效引擎。 竞墨的教训：骨架不是墨缘那种架构 → 切页像划照片，后期花大力气补统一入场引擎，仍难完全追平原生丝滑。这是架构选型的债，最后用体验来还；别信"先能用，动效以后再说"。
  • 选骨架时直接问一句：它原生支持丝滑切场吗？ 如果不支持，要么一开始就接受"手感次一档"并明确取舍，要么换架构——不要事后才发现。
  • 身份字段只定一个源；令牌与身份双键成对写、成对清；401 统一清空整套。
  • 前端藏入口 + 后端守卫双保险；401 登出 / 403 不登出要分清。403 绝不能触发登出——墨缘就是 401/403 一起广播"身份失效"，形成"重登→第一个403→又登出"的死循环。
  • 身份数据只存一张表：墨缘的 admins 和 class_students 双表哈希不同步，登录查一张、改密写另一张 → 改密永远失败。身份别散在两处。
  • 名单/权限显示异常，先查接口返回：很多是前端自己多套了一层 isAdmin 把数据藏了，接口本来就是全量。
  • 页面与入口一一对应要逐个点验：墨缘两个按钮跳同一页面、已加入还显示"我要加入"，都是前端没套状态判断。
  • 首登改密的流程要能走通，别把用户锁死在"必须改密"的死锁里。
  • 删除/清空类操作要二次确认（管理密码 / 输入特定词）。
  • 报"全员掉线"先分清环境：豆包/编辑器预览（dev）和正式版往往不是一套登录环境。先问版本号、测的是哪个环境，别急着改代码。

C. 数据层

  • 唯一判据思维：发布看 commit hash，不看"构建成功"；功能上线看实测接口/页面，不看自报。
  • 数据存本地就要有导出/导入兜底；存云端就要有备份策略。
  • 以日期字符串为随机种子，保证"同日刷新计划不变"。
  • 内容脏数据单独核验，功能对不代表内容对。

D. 性能与图片

  • 列表一律缩略图 + 懒加载，详情用原图；CDN 参数要编码形式。
  • 上传前必压缩：前端 canvas 压到长边 1600px / 单张 <1MB；提交前估算总量拦截超限；错误提示区分"体积大"和"网络差"。38MB 是实测的代理断连阈值。
  • 声称的限流/上限要实测，不信注释。

E. 视觉与排版

  • 先立总纲再写页面（见第四部分模板 E）。设计令牌全变量化；容器 box-sizing+自动换行兜底；nowrap 只许用于单个英文单词；强调色唯一；正文 ≥16px；公式要渲染。
  • 配色在色环上拉开色相，别让两种小标签糊成一类。
  • 视觉验收用普通用户视角，别用 admin 编辑态。

E2. 前端交互高频坑（"点了没反应"类，最容易被漏测）

  • 入口 HTML 要有底色、遮罩先于内容挂载：否则手机上冷启动盯 2~4 秒白屏；装饰层对比度太低等于没有。
  • input.files 是 live FileList：存引用后 value='' 会把它清空，导致"选完图零请求零报错"。先 Array.from() 拷贝再清空。同类 bug 常被复制到多个入口，修一处要全线排查。
  • 移动端面板高度要扣掉底部 tab：否则"保存"按钮落在可视区外，点它其实命中底部导航。
  • 装饰层（水印/悬浮球）不能盖住可点元素：z-index 分层要验。
  • "关窗≠执行"：确认弹窗关闭后要验后端数据真的变了（接口请求发出、刷新后状态改变）。
  • 别用自动化脚本的"最后一个某文字按钮"定位元素：会命中隐藏候选导致误判；误判要复测推翻再写根因。
  • 移动端别乱用 touch-action:none：会让列表滑不动，用 pan-y。

F. 动效

  • 统一引擎：只 opacity/transform，幂等标记，播一次固化，getAnimations() 检测复播，禁止 display/height/width 动画。
  • 进度条宽度是 layout 变化，入场时直接呈现最终宽度，不要逐帧 animate width。
  • 角色动画朝向由单一变量控制，左右方向都验。

G. 验收（最重要）

  • 别信自报："已修复""本地测是好的""发布一下才能看日志"——一律要它在预览里测、把错误原文露出来。
  • 自己点通关键动作，每轮发布后手机过 5 个关键路径。
  • 证伪思维：看到"缺某功能"先实测确认它本来是不是就没有，别急着补。
  • 同一问题改 3 轮还不好 → 回退重新描述，别继续猜。
  • 把判读规则写进文件（如墨缘的"自检 error 是运营待办不是 bug"），不靠记忆。

H. 成本（用 AI 改代码时）

  • 同类改动合并一次发，别切碎（每次新任务都要重读代码库）。
  • 机械活（加参数/改文案/换色）用最便宜的模型；判风险/大上下文用贵模型；别中途换模型。
  • 验收用本地脚本，别让 AI 反复 build + 截图。
  • 指令要明确具体，别用"自己找最省办法"这种会诱发过度推理的话。

I. 删除与发布安全（防"静默失败"）

  • "不报错"不等于"没人用"：删掉一段代码/请求头/字段后不报错、构建成功、资源全 200，也可能被平台或别的模块悄悄依赖，一删全站崩。
  • 删除/重命名前必答影响面四问：还有谁在读？删了谁会静默失败？能否先加后删？怎么在 5 分钟内证明没人用（全仓搜+查文档+测试环境单独删一次）。
  • 分层验证，别只看 200：L0 传输（200）→L1 文档（HTML 对）→L2 渲染（浏览器看见内容）→L3 运行时（关键变量正确、无 console error）→L4 业务（写入读回）。状态码 200 只证明第一层。
  • 出事第一动作是回退，不是查因；回退目标=上一个已知良好版本；恢复后再分析。
  • 线上正坏着时禁止顺手优化——只回退或等指令，别给下次故障埋变量。
  • 听到"这个应该不影响别的功能""接口都 200 应该是好的"立刻叫停——这是事故前的原话信号。

第三部分 · 大项目 vs 小项目：怎么选架构

维度 小项目（专升本） 大项目（墨缘 / 竞墨）
典型场景 个人用、一两人私发 多人报名投稿、要统计和权限
前端形态 单文件 HTML 多页 Web App / 单文件 + 后台接口
骨架选型（决定手感上限） 单文件也能丝滑，但切场机制要在骨架里就内建 先问"原生支持丝滑切场吗"——竞墨选错骨架→像划照片，后期补引擎仍追不平墨缘
数据 localStorage + 导出 JSON 数据库 + 服务端接口
登录 不要，私发链接即可 必须，身份单一源 + 双保险守卫
备份 导出/导入 JSON 服务端备份 + 发布纪律
性能重点 基本不用管 图片压缩、上传体积、并发
动效 统一引擎骨架期就内建 统一引擎 + 朝向变量 + 幂等；后期补=还架构债
主要风险 数据丢失、样式失控、脏数据 权限漏洞、发布误判、大图上传、测试污染真实数据
施工节奏 快速迭代，但先立总纲 五阶段不跳，地基先行

判断口诀： - 要不要登录？—— 超过"几个熟人私用"就要，否则不要。 - 要不要后台？—— 需要跨设备同步、多人权限、数据统计才要。 - 要不要总纲？—— 永远要，哪怕只有一个页面。这是"做一个改一个"和"一次立规"的分水岭。

模板 B · 提需求五行

【改什么】一句话说清
【在哪】哪个页面、哪个按钮
【改成什么样】具体行为，不要形容词（"好看一点"不合格）
【怎么算成功】我点几下、看到什么
【不要动】列出绝对不能碰的模块（动效/计划/数据/其他页面）

反面例子："把页面优化一下""感觉很乱"——这类话会让它一次改五个文件。

模板 C · 施工提示词（R 编号制）

### 提示词 R<N> · <一句话标题>（模型 <档位>；<日期>，<触发原因>）

> 【问题】用户原话 + 截图实证，写清现象，不写"感觉"
> 【根因】定位到具体机制（不要停在"样式坏了"）
> 【改法】分点，写到能直接抄的代码/CSS 级别
> 【红线】不许碰什么（列具体模块名）
> 【验收】点几下看到什么 + 报告计算样式/接口返回值

规矩：一条需求一个 R 编号；复杂的用 R3.1/R3.2 递增；总纲类（如 R3.8）优先级最高，写明"其它条目与本节冲突以本节为准"。

模板 D · 验收清单

□ 关键动作自己点通（不是听它说"已修复"）

模板 E · 全站排版总纲（每个项目都该有一份）

# 全站排版总纲（优先级高于所有零散补丁）

1. 设计令牌：:root 里定义颜色/字号/间距/圆角/阴影，组件只引用变量，不写死值
2. 容器与换行：*{box-sizing:border-box}；文本容器 max-width:100% + overflow-wrap:break-word；
   nowrap 只许用于单个英文单词/数字
3. 通用组件：警示条/按钮/标签/卡片/提示条统一 class，禁止浏览器默认样式露出
4. 强调色唯一：主操作专用，标签/装饰不许抢
5. 公式渲染：KaTeX + 离线降级，页面不得出现裸 LaTeX
6. 字号层级：标题 20 / 正文 16 / 辅助 ≥13，行高 1.75
7. 自检清单：每页上线前逐条过（见模板 D）

模板 F · 发布纪律

1. 发布生效唯一判据：commit hash / 版本号变化，不信"构建成功"
2. 发布前弄清这次会带哪些 commit
3. 主分支禁 force push，特性分支用 --force-with-lease
4. 删除/重命名任何头/字段/路由/策略前，先答"影响面四问"，答不出不许删
5. 发版后分层验证：L0传输→L1文档→L2渲染→L3运行时→L4业务，"浏览器看见内容+截图"才算数，200 不算
6. 出事第一动作是回退（到上一个已知良好版本），不是查因；故障期禁止顺手优化
7. 发布前自己点通，发布后手机过 5 个关键动作
8. 每 3-5 条改动导一次备份、记版本号

模板 G · 收工三行（每次会话结束写）

日期：
这一版能做什么：（三条以内）
已知没做/没验：（一条一行）

下次开工先看这三行，就不会"完全搞混了"。

模板 H · 微文案表（M8 落地｜错误/状态提示只准从这里抄，AI 不许自己发挥）

规矩：任何提示文案固定三段式——发生了什么 + 为什么 + 现在怎么办；按钮用动词；禁止"请稍后重试""网络异常""操作失败"这类零信息话。

场景 固定文案（直接抄）
图片体积过大 「图片太大了（约 X MB），一次最多传 Y MB。请先删掉几张，或换小一点的图再试。」
上传断连 「上传中断了。图片总量太大时容易断，减少张数再试一次；还是不行就先把作品存好，稍后再传。」
网络失败（一般接口） 「刚才的请求没成功，可能是网络不稳。内容已帮你保留，点"重试"再试一次。」
无数据（空态） 「这里还没有内容——完成一次练习后就会出现在这里。」（+ 一个"去练习"按钮）
未登录/登录失效 「登录已过期，需要重新登录一次。你之前填写的内容不会丢，登录后可继续。」
提交成功 「已提交成功。」（需说明结果去向时补一句，如"评分结果稍后在我的作品里查看"）
提交失败 「提交没成功，内容还在页面上没有丢。点"重新提交"再试；连续失败请截图右下角红点发给制作方。」
数据加载失败 「内容加载失败（可能是网络或服务暂时不可用）。点"重新加载"；问题持续请截图右下角红点。」

注：文末"截图右下角红点"指向 R3.9 错误红点机制；红点未上线的站删掉这句。

模板 I · 发布台账 RELEASES.md（M2 落地｜防"线上旧产物 / 仓库新源码"分裂）

每个项目根目录建一个 RELEASES.md，每次发布后追加一行，新在上：

| 日期 | 改了什么 | 线上文件指纹（字节数+md5前8位） | 对应源码提交/备份文件名 | 谁验的、怎么验的 |
|---|---|---|---|---|
| 2026-11-24 | R3.9 错误红点 | 152,340 字节 / a1b2c3d4 | backup_20261124_2130.html | 本人：断网点提交→红点→刷新仍在 |

三条规矩： 1. 发布前先存线上版（备份文件名写进台账），改完发布再补一行——顺序不能反。 2. 回退 = 按台账找到上一个"已验收"行，取它的备份文件重传，不看别的。 3. 台账里找不到对应备份的行，视为"这次发布没发生"，必须补齐才能继续发下一版。

模板 J · 症状速查表（M12 落地｜独立存放，给用户自己查，不随本文档喂 AI——省积分）

不放在本文档里（本档是开工喂给 AI 的，症状表是出事时人自己查的，混在一起每次多读一屏字）。完整表格独立存于 症状速查表.md（11 行"症状 → 第一动作 → 高频根因"）。

给 AI 只需记住三条提炼： 1. 全站打不开 → 先回退再查因（最大嫌疑：动了平台注入的东西） 2. 白屏/点了没反应 → 先取证（红点、console、截图），别凭感觉改 3. 提交"成功"数据没变 → 直接查数据源，别信界面

模板 K · 通用巡检（M1 落地｜证据制，结论看文件不看转述）

工具：/workspace/tools/网页巡检.py（已在埋坑测试页上实测：console 报错、资源 404、横向溢出、裸 \frac 禁词、错误红点历史全部抓到）。

用法（每站一份配置 JSON，已建好骨架：巡检配置_专升本.json / 巡检配置_竞墨.json，把线上链接填进去即可）：

python3 /workspace/tools/网页巡检.py --config /workspace/tools/巡检配置_专升本.json

铁律： 1. 结论只在产物文件里——巡检结果_<站>_<时间>/ 下的 PNG 截图 + results.json + index.md。AI 转述的"X 项过"不算数，你自己开 index.md 看 FAIL/WARN 表。 2. 退出码 0=全过、1=有 FAIL，可用于自动拦截。 3. 固定检查项不需要配置自动跑：HTTP 状态/重定向链、标题断言、入口底色（防白屏）、console 报错（滤噪声）、资源 4xx/5xx、横向溢出检测、禁词扫描（裸 LaTeX/零信息文案）、错误红点 localStorage 读取（与 R3.9 打通）、动作回放每步截图。 4. 每站把"5 个关键动作"写进配置的 actions（点哪、等哪、截哪），巡检就替你把验收路径回放一遍。 5. 噪声（如字体 CDN 的 octet-stream）写进配置 noise，不算错——但往 noise 里加东西前要说明理由，不许拿来掩盖真问题。

五、踩坑速查红线（打印贴墙上）

  1. "构建成功/已修复/本地测是好的"一律不算数 —— 要唯一判据 + 预览实测。
  2. 发布看 hash，不看提示。
  3. 骨架定手感上限——切场/导航/动效引擎在骨架期就定死，别信"以后再补"（竞墨划照片之痛）。
  4. 身份只有一个源，401/403 分清，双键成对清。
  5. 上传前必压缩，38MB 是断连阈值。
  6. 删东西前答影响面四问——"不报错"不等于"没人用"（删请求头→全站打不开之痛）。
  7. 发版分层验证，200 只证明第一层；出事先回退后查因。
  8. 先立总纲再写页面，做一个改一个是万恶之源。
  9. 强调色唯一，配色拉开色相。

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
网页巡检 · 通用模板（证据制）
--------------------------------------------------
一条命令跑完一个站的发布后验收，产物落目录：截图 PNG + results.json + index.md。
**结论只在文件里，不在对话里转述**——看证据不看汇报。

用法：
    python3 网页巡检.py --config 巡检配置_专升本.json
    python3 网页巡检.py --config 巡检配置_专升本.json --quick   # 跳过浏览器，只做 HTTP 层
    python3 网页巡检.py --config xxx.json --out ./巡检结果       # 指定输出目录

配置文件（每站一份 JSON，字段见下方 CONFIG 说明）：
    name            站名（用于产物目录命名）
    url             线上正式地址（必填）
    title_contains  页面标题应包含的字样（列表，任一命中即过）
    viewport        手机视口，默认 375x812
    key_selectors   关键元素清单 [{name, selector}]，逐个验存在+可见
    actions         动作回放 [{name, do: click|goto|wait, target}]，每步截图
    noise           console 已知噪声（列表，模糊匹配后不算错）
    forbid_texts    禁词清单（如裸 LaTeX 命令串、"请稍后重试"零信息文案）
    errlog_keys     错误红点 localStorage 键（如 zx_errlog_v1），巡检顺带读出

固定检查项（不需要配置，所有站自动跑）：
  HTTP    状态码、重定向链、最终 URL、HTML 体积、入口底色（body 有无背景，防白屏）
  浏览器  console 报错（滤噪声）、资源 4xx/5xx、首屏截图（手机视口）
  布局    横向溢出检测（scrollWidth > clientWidth 即 FAIL）
  红点    读 localStorage 错误日志键，有记录则列进 results.json

依赖：requests、playwright（缺 playwright 自动降级为 --quick 模式）
退出码：0 = 全 PASS；1 = 有 FAIL。产物目录路径打印在最后一行。
"""

import argparse
import json
import os
import sys
import time
from datetime import datetime

import requests

UA = ("Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) "
      "AppleWebKit/605.1.15 (KHTML, like Gecko) Mobile/15E148 Safari/604.1")
DEFAULT_ERRLOG_KEYS = ["zx_errlog_v1", "jm_errlog_v1"]


def load_config(path):
    with open(path, encoding="utf-8") as f:
        cfg = json.load(f)
    if not cfg.get("url"):
        sys.exit("配置缺 url")
    cfg.setdefault("name", "site")
    cfg.setdefault("viewport", {"width": 375, "height": 812})
    cfg.setdefault("title_contains", [])
    cfg.setdefault("key_selectors", [])
    cfg.setdefault("actions", [])
    cfg.setdefault("noise", [])
    cfg.setdefault("forbid_texts", [])
    cfg.setdefault("errlog_keys", DEFAULT_ERRLOG_KEYS)
    return cfg


class Report:
    """所有结论先进这里，最终落 results.json；对话里只打单行进度。"""

    def __init__(self):
        self.items = []
        self.shots = []

    def add(self, level, name, detail="", evidence=""):
        self.items.append({"level": level, "name": name,
                           "detail": str(detail)[:500],
                           "evidence": str(evidence)[:500]})
        icon = {"PASS": "PASS", "FAIL": "FAIL", "WARN": "WARN"}.get(level, "?")
        print(f"  [{icon}] {name}" + (f" — {detail}" if detail else ""))

    def count(self, level):
        return sum(1 for i in self.items if i["level"] == level)

    def dump(self, outdir):
        path = os.path.join(outdir, "results.json")
        with open(path, "w", encoding="utf-8") as f:
            json.dump({"items": self.items, "shots": self.shots,
                       "summary": {"pass": self.count("PASS"),
                                   "fail": self.count("FAIL"),
                                   "warn": self.count("WARN")}},
                      f, ensure_ascii=False, indent=2)
        return path


def http_layer(cfg, rep, outdir):
    s = requests.Session()
    s.headers["User-Agent"] = UA
    r = s.get(cfg["url"], timeout=30, allow_redirects=True)
    chain = " -> ".join([h.status_code.__str__() + " " + h.url
                         for h in r.history] + [str(r.status_code) + " " + r.url])
    rep.add("PASS" if r.status_code == 200 else "FAIL",
            "HTTP 状态", f"最终 {r.status_code}", chain)
    # 按字节再显式 utf-8 解码，避免服务器未带 charset 时 requests 猜错编码（中文标题乱码）
    html = r.content.decode("utf-8", errors="replace")
    title = ""
    import re
    m = re.search(r"<title[^>]*>(.*?)</title>", html, re.S | re.I)
    if m:
        title = m.group(1).strip()[:80]
    if cfg["title_contains"]:
        ok = any(t in title for t in cfg["title_contains"])
        rep.add("PASS" if ok else "FAIL", "页面标题", title,
                f"应包含: {cfg['title_contains']}")
    else:
        rep.add("WARN", "页面标题（未配置断言）", title)
    kb = len(html.encode("utf-8")) / 1024
    # 入口体积只防"空壳 HTML"：过小给 WARN 不给 FAIL（小站入口本来就可能小）
    if kb < 0.5:
        rep.add("FAIL", "HTML 体积", f"{kb:.2f} KB，疑似空壳")
    elif kb < 1:
        rep.add("WARN", "HTML 体积", f"{kb:.1f} KB，偏小（可能是空壳，配合首屏截图判断）")
    else:
        rep.add("PASS", "HTML 体积", f"{kb:.1f} KB")
    # 入口底色：body/background 任一有颜色定义（防冷启动白屏）
    has_bg = bool(re.search(r"background[^;{}]*#|background[^;{}]*rgb|<body[^>]*bgcolor",
                            html, re.I))
    rep.add("PASS" if has_bg else "WARN", "入口底色（防白屏）",
            "找到背景定义" if has_bg else "HTML 里没找到背景色，冷启动可能白屏，建议入口 HTML 带 body 底色")
    with open(os.path.join(outdir, "入口.html.txt"), "w", encoding="utf-8") as f:
        f.write(html[:200000])
    return html


def browser_layer(cfg, rep, outdir):
    try:
        from playwright.sync_api import sync_playwright
    except ImportError:
        rep.add("WARN", "浏览器层", "playwright 未安装，自动降级（只有 HTTP 层证据）")
        return

    with sync_playwright() as p:
        browser = p.chromium.launch()
        page_kwargs = dict(viewport=cfg["viewport"], user_agent=UA, device_scale_factor=2)
        if cfg.get("color_scheme"):
            page_kwargs["color_scheme"] = cfg["color_scheme"]
        if cfg.get("reduced_motion"):
            page_kwargs["reduced_motion"] = "reduce"
        page = browser.new_page(**page_kwargs)
        console_errs, bad_reqs = [], []

        page.on("console", lambda m: console_errs.append(m.text) if m.type == "error" else None)
        page.on("response", lambda r: bad_reqs.append(f"{r.status} {r.url}")
                if r.status >= 400 else None)

        try:
            page.goto(cfg["url"], timeout=30000, wait_until="networkidle")
        except Exception as e:
            rep.add("FAIL", "页面加载", str(e)[:200])
            browser.close()
            return
        page.wait_for_timeout(800)
        shot = os.path.join(outdir, "01_首屏.png")
        page.screenshot(path=shot)
        rep.shots.append(shot)
        rep.add("PASS", "首屏截图", shot)

        # console 报错（滤噪声）
        noise = cfg["noise"]
        real = [e for e in console_errs if not any(n in e for n in noise)]
        rep.add("PASS" if not real else "FAIL", "console 报错",
                f"{len(real)} 条" if real else "无",
                "; ".join(real[:5]) if real else "")

        # 资源 4xx/5xx
        rep.add("PASS" if not bad_reqs else "FAIL", "资源可达性",
                f"{len(bad_reqs)} 个失败" if bad_reqs else "全部可达",
                "; ".join(bad_reqs[:8]) if bad_reqs else "")

        # 关键元素
        for ks in cfg["key_selectors"]:
            try:
                el = page.query_selector(ks["selector"])
                visible = bool(el and el.is_visible()) if el else False
                rep.add("PASS" if visible else "FAIL",
                        f"关键元素·{ks['name']}",
                        "存在且可见" if visible else "缺失或不可见", ks["selector"])
            except Exception as e:
                rep.add("FAIL", f"关键元素·{ks['name']}", str(e)[:120], ks["selector"])

        # 横向溢出
        overflow = page.evaluate(
            "() => document.documentElement.scrollWidth - document.documentElement.clientWidth")
        rep.add("PASS" if overflow <= 1 else "FAIL", "横向溢出",
                f"超出 {overflow}px" if overflow > 1 else "无")

        # 禁词
        body_text = page.evaluate("() => document.body.innerText")
        hits = [t for t in cfg["forbid_texts"] if t in body_text]
        rep.add("PASS" if not hits else "FAIL", "禁词扫描",
                "未命中" if not hits else f"命中 {len(hits)} 个", "; ".join(hits[:5]))

        # 正文对比度（浅/深色都要 ≥4.5，WCAG AA 正文级；由实际计算色算，不凭感觉）
        if cfg.get("contrast_check"):
            ratio = page.evaluate("""() => {
                function lum(c){
                  const m = c.match(/[\\d.]+/g); if(!m) return null;
                  const [r,g,b] = m.slice(0,3).map(Number).map(v=>{
                    v/=255; return v<=.03928 ? v/12.92 : Math.pow((v+.055)/1.055,2.4)});
                  return .2126*r+.7152*g+.0722*b;
                }
                function bgOf(el){
                  let e=el;
                  while(e){ const b=getComputedStyle(e).backgroundColor;
                    if(b && b!=='rgba(0, 0, 0, 0)' && b!=='transparent') return b;
                    e=e.parentElement; }
                  return 'rgb(255,255,255)';
                }
                const cs=getComputedStyle(document.body);
                const L1=lum(cs.color), L2=lum(bgOf(document.body));
                if(L1==null||L2==null) return -1;
                return (Math.max(L1,L2)+.05)/(Math.min(L1,L2)+.05);
            }""")
            try:
                ratio = round(float(ratio), 2)
                if ratio >= 4.5:
                    rep.add("PASS", "正文对比度", f"{ratio}:1（≥4.5 达 AA）",
                            f"色系: {cfg.get('color_scheme','light')}")
                elif ratio >= 4.0:
                    rep.add("WARN", "正文对比度", f"{ratio}:1（4.0-4.5 边缘，大字号可接受）", "")
                else:
                    rep.add("FAIL", "正文对比度", f"{ratio}:1（<4.0 弱光看不清）", "")
            except Exception as e:
                rep.add("WARN", "正文对比度", "计算失败: "+str(e)[:80], "")

        # 错误红点 localStorage
        for key in cfg["errlog_keys"]:
            try:
                raw = page.evaluate(f"() => localStorage.getItem({json.dumps(key)})")
            except Exception:
                raw = None
            if raw:
                rep.add("WARN", f"错误红点·{key}", "有历史错误记录（详见 results.json）", raw[:400])
            else:
                rep.add("PASS", f"错误红点·{key}", "无历史错误")

        # 动作回放
        for i, act in enumerate(cfg["actions"], 1):
            name, do, target = act.get("name"), act.get("do"), act.get("target", "")
            ok, detail = True, ""
            try:
                if do == "click":
                    page.click(target, timeout=8000)
                    page.wait_for_timeout(600)
                elif do == "fill":
                    page.fill(target, act.get("value", ""), timeout=8000)
                    page.wait_for_timeout(200)
                elif do == "goto":
                    page.goto(target, timeout=20000)
                elif do == "wait":
                    page.wait_for_timeout(int(target))
                elif do == "run":
                    page.evaluate(target)
                    page.wait_for_timeout(200)
                elif do == "upload":
                    page.set_input_files(target, act.get("value", ""), timeout=8000)
                    page.wait_for_timeout(600)
                elif do == "check":
                    truth = page.evaluate(target)
                    if not truth:
                        raise RuntimeError("断言未通过: " + str(target)[:150])
                    page.wait_for_timeout(200)
                else:
                    raise RuntimeError(f"未知动作类型: {do}")
                shot = os.path.join(outdir, f"{i + 1:02d}_{name}.png")
                page.screenshot(path=shot)
                rep.shots.append(shot)
                detail = shot
            except Exception as e:
                ok, detail = False, str(e)[:200]
            rep.add("PASS" if ok else "FAIL", f"动作·{name}",
                    detail, f"{do} {target}")

        browser.close()


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--config", required=True)
    ap.add_argument("--quick", action="store_true", help="只跑 HTTP 层")
    ap.add_argument("--out", default=None)
    args = ap.parse_args()

    cfg = load_config(args.config)
    ts = datetime.now().strftime("%m%d_%H%M")
    outdir = args.out or f"巡检结果_{cfg['name']}_{ts}"
    os.makedirs(outdir, exist_ok=True)
    rep = Report()

    print(f"== 网页巡检 · {cfg['name']} · {cfg['url']} ==")
    http_layer(cfg, rep, outdir)
    if not args.quick:
        browser_layer(cfg, rep, outdir)

    res = rep.dump(outdir)
    md = os.path.join(outdir, "index.md")
    with open(md, "w", encoding="utf-8") as f:
        f.write(f"# 巡检产物 · {cfg['name']} · {datetime.now():%Y-%m-%d %H:%M}\n\n")
        f.write(f"- PASS {rep.count('PASS')} / FAIL {rep.count('FAIL')} / WARN {rep.count('WARN')}\n")
        f.write(f"- **检查范围：HTTP 层=入口全量；浏览器层=首屏 + 配置 actions 覆盖到的页面（本站共 {len(cfg['actions'])} 个动作）。PASS ≠ 整站干净，只代表已覆盖范围干净。**\n")
        f.write("- FAIL/WARN 明细见 results.json，截图见 PNG\n\n| 结果 | 项 | 说明 |\n|---|---|---|\n")
        for i in rep.items:
            if i["level"] != "PASS":
                f.write(f"| {i['level']} | {i['name']} | {i['detail']} |\n")
    print(f"\n产物目录：{os.path.abspath(outdir)}")
    print(f"结论看文件，不看转述：{os.path.abspath(md)}")
    sys.exit(0 if rep.count("FAIL") == 0 else 1)


if __name__ == "__main__":
    main()
