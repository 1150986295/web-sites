## 三、接到需求后的标准流程（照做）

### 第 1 步：判断站型（决定用哪个模板）

- **纯展示、不登录、不存数据** → 模板A
- **要登录、后台、多人数据、表单提交** → 模板B
- 拿不准 → 问项目主人一句，别猜

### 第 2 步：读规矩（别跳过）

读 `docs/00_做网页的规矩_总纲.md` 和对应模板的使用说明。规矩里写了"五阶段不跳"、"五行提需求格式"——这是这个项目做过三个站总结出来的，跳过就翻车。

### 第 3 步：基于模板复制，不要从零另写

- **模板A**：按 `docs/模板A_使用说明.md` 的 5 步——改三色、换图、改文字
- **模板B**：按 `docs/模板B_使用说明.md` 的 8 步——**先改路由表 `ROUTES` 再加页面**，否则启动报错；身份逻辑已内置别删
- **红线**：路由表、切场引擎、设计令牌、错误红点、三态、401/403 分流、幂等键、备份导入导出——这些都是防坑件，**一个字都不要删**

### 第 4 步：验收（机械判断，不靠感觉）

```bash
python3.11 开工包/tools/验收门禁.py <你做出来的.html>
```

- 有任意 FAIL → 自己修到全绿，别交出去
- 全绿 → 再用浏览器真点一遍：每个页面能切、按钮有反应、无错误红点、手机不横向溢出

### 第 5 步：交给项目主人 / 推仓库

- 你**不要**自己改仓库、不要碰 token——把做好的 html 和门禁结果发给项目主人
- 推仓库由主线 AI 按 `docs/03_验收与推仓库流程.md` 做（token 已嵌在仓库配置里）

## 四、给 AI 的关键提醒（血泪教训）

1. **别从零写**：项目主人要做的是"从模板复制出一个 bug 少的站"，不是让你自由发挥写新架构。模板里每一条防坑规矩都是三个真实项目踩出来的。
2. **别塞外链**：CDN、外部字体、在线图片一律不许——断网就裂。全内联或本地相对路径。
3. **别带回平台水印/署名**：项目主人要的是完全自有、无水印的产品。
4. **需求要具体**：如果项目主人说"做个好看的站"，你要追问具体功能（有哪些页面、什么按钮、什么风格、给谁用），别自己脑补。
5. **改完必须验**：门禁脚本不是摆设，先跑再交。
6. **做交互先查参考库**：网页要加交互效果时，先读 `开工包/reference/INTERACTIONS.md` 的「场景速查表」，从中挑 1-3 个最匹配的，按详情的「实现要点/验收条件」落地；动画必须给 `prefers-reduced-motion` 静态替代，优先原生 CSS/JS，别照搬参考库文案。
   - 想要**现成可跑的实现**：86 项全部已在 `interactive-lab/index.html` 里落地为本地演示（`DEMOS` 表，每项 `{hint, html, run}`，零依赖、不跳外链）。做法与验收见 `docs/12_交互参考库_本地演示台.md`，复制 `reg()` 定义即可复用。
