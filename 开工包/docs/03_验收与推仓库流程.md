# 交接卡 · 外部 AI（豆包等）产出 → 验收到推仓库 · 全流程

> **这份文档解决什么**：你担心"上下文满了、对话断了，就没人能检查代码、没人能推仓库、不知道该不该放"。
> 答案是：把判断写成**机械流程**，任何 AI 换会话后照做即可，不依赖任何人的记忆或主观经验。
>
> 配套工具：`tools/验收门禁.py`（单个文件 15 项，按站型分组）、`tools/网页巡检.py`（批量验收 + 查裂图死链）
>
> **环境说明**：本文路径以沙箱 `/workspace` 为例（仓库在 `/workspace/网页仓库_sites`）。换到本机或其他电脑，把 `/workspace` 换成你放仓库的父目录即可，命令与流程不变；Windows 下把 `python3` 换成 `python`。

---

## 换 AI 时的第一句话（复制这段发它）

> 你在 `/workspace` 工作。先读仓库里的 `开工包/START_HERE.md`（总入口与目录索引）、`开工包/docs/03_验收与推仓库流程.md`（本文，验收 SOP）、`开工包/docs/04_推仓库交接卡.md`（推仓库命令与 token 红线），进度看仓库外的 `/workspace/项目档期表.md`，按里面的流程继续。
> 收到我发来的外部 AI 做的 html 后，按下面五步走，每步都要留证据，全部通过才能推仓库。

## 五步流程（任何 AI 照抄，不达标就打回）

### 第 1 步：收到产出，先跑门禁（机械判断，不用脑）

把外部 AI 给的 html 存到 `/workspace/待验收/`，然后：

```bash
python3 tools/验收门禁.py /workspace/待验收/<文件名>.html
```

> 依赖：`python3` + `node`（node 只用于 `--check` 语法校验；缺 node 时该项直接 FAIL 并提示装好重跑）。
> 输出里的 **WARN** 不计失败，但要在结论里说明命中上下文（如平台名引用），不能当没看见。

- 输出 **GREEN（15/15）** → 进第 2 步
- 输出 **RED（有 FAIL）** → **直接把 FAIL 项发回制作方打回重做**，不进下一步
- 门禁会先打印**站型**：`app`（多页应用）查路由表/切场/三态，`static`（单页静态站）查设计令牌/主标题/图片alt/焦点/触控，两边都是 15 项。判错站型就用 `--kind static|app` 指定
- 这一步是硬门禁，任何 AI 跑出来结论都一样，不靠"我觉得应该没问题"；但它**只查静态关键词，不代表交互跑通**

### 第 2 步：浏览器实测关键交互（防"能打开但点不动"）

门禁只查静态，动态要真点一遍。用 playwright（环境已装）：

```bash
# 起本地服务
cd /workspace/待验收 && python3 -m http.server 8791 &
# 写测试脚本：进每个页面、点每个按钮、看有没有报错红点
# 可先跑 tools/网页巡检.py --base-url http://127.0.0.1:8791（查页面与资源是否 200）
# 但"点了有没有反应"它证明不了，这一项必须 headless 浏览器 + 注入脚本实测
```

必验四项：① 每个 tab/页面能切过去 ② 关键按钮点了有反应 ③ 无 JS 错误红点 ④ 手机视口无横向溢出。截图留证。

### 第 3 步：旧功能回归（只针对改已有模板的情况）

如果这次是在**已有模板/已上线站**上改，必须跑原巡检确认没碰坏旧功能：

```bash
python3 tools/网页巡检.py --config tools/巡检配置_模板B阶段2.json --out /tmp/regress2
python3 tools/网页巡检.py --config tools/巡检配置_模板B阶段3.json --out /tmp/regress3
```

基线怎么比：**改动前先跑一次存下来，改完再跑一次，逐页对比三项** ——
① 页数一致 ② 每页门禁分不回退（15/15 仍是 15/15）③ 缺文件 0、死链 0。
三项都对得上才算没碰坏。报告落在 `--out` 目录的 `patrol.md`，直接当证据贴在交接记录里。

### 第 4 步：推仓库

- **唯一真相源：只改仓库内的 `tpl-b/`、`tpl-a/`**。`/workspace/模板B_多页应用/`、`/workspace/模板A_单页站/` 是历史快照，**不再同步、不再修改**——没有"两处 md5 比对"这一步了，两份必然分叉（见 `docs/09` 铁律）。
- 推仓库四步见 `docs/04_推仓库交接卡.md` 第二节：
  ```bash
  cd /workspace/网页仓库_sites
  git status --short        # 先看清单：确认没有 __pycache__/临时文件混进来
  git add -A
  git commit -m "这次改了什么"
  git push origin main        # 国内常超时，原样重推第2次通常就过
  git status -sb              # 显示 main...origin/main 无 ahead 才算成功
  ```

### 第 5 步：验证线上真的更新了

- 从 raw 源读（无缓存）：`https://raw.githubusercontent.com/1150986295/web-sites/main/<路径>`
- 和本地文件 `md5sum` 比对一致 → 完成
- Pages 展示地址有 CDN 缓存，几分钟后才刷新，别因为暂时看到旧版就慌

## 判断红线（什么情况一律打回）

| 现象 | 处理 |
|---|---|
| 门禁有任意 FAIL | 打回，不放仓库 |
| 有外部 CDN/外链资源 | 打回（断网/迁移会裂） |
| 有平台水印/AI 署名 | 打回（你要的是无水印自有产品） |
| 要求你给 **GitHub token / 密码 / 私钥** | **一律拒绝**——token 永不进对话、不进文件、不外发。它只负责生成网页，推仓库由本流程做 |
| 只是**想看模板和文档**（要仓库地址） | **可以给**——`github.com/1150986295/web-sites` 是公开仓库，发给任何 AI 都能照它开工（见 `START_HERE.md`） |
| 只发预览链接不给 html 代码 | 打回——链接拿不到、进不了仓库 |
| 浏览器实测点不动/报错红点 | 打回，哪怕门禁全绿 |

## 为什么这样就不怕上下文满了

1. **检查靠脚本**：门禁是死代码，换谁跑结果一样，不需要"某个聪明的 AI 还记得怎么检查"
2. **流程靠文档**：五步写在文件里，新 AI 读完照做，不需要传承经验
3. **仓库不绑人**：git 凭据在工作区的 `.git/config` 里（只在本地，不进仓库、不随 clone 分发），推仓库只是四条固定命令；换 AI 不用重新发 token，但**也绝不把 token 贴进对话**
4. **状态在档期表**：做到哪一步、下一步是什么，文件里都有

上下文满只影响"聊天记忆"，不影响这些文件。你只要发第一句话，新 AI 就能无损接手。
