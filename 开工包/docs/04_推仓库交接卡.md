# 交接卡 · 推仓库（2026-11-25）

> **回答那个问题**：推仓库**不是只能由某一个 AI 做**。任何能访问这个工作区的 AI、或你以后有电脑时自己，只要拿到这个工作区 + 这张卡，就能推。
> 绑人的不是"某个 AI"，而是**工作区里的 git 凭据**：token 只存在本地 `.git/config` 的 remote URL 里（不进仓库、不随 clone 分发）。
>
> **token 三条红线**（任何情况下都不破）：
> 1. **不进对话**——不贴给 AI、不让 AI 复述、不在聊天里出现（聊天记录会留存、会进模型上下文、会出现在日志里）。
> 2. **不进文件**——不写进任何 `.md` / `.html` / 脚本 / 提交信息，仓库是公开的。
> 3. **不外发**——不发给任何人、不填进第三方网站；只在 GitHub 设置页和你自己的终端里存在。

## 一、上下文满了怎么办（你真正担心的）

对话上下文满了，AI 会压缩/换新会话，但**进度不会丢**，因为所有状态都存在文件里：

| 文件 | 作用 |
|---|---|
| `/workspace/项目档期表.md`（仓库外） | 全局进度：哪些做完、哪些待办、下一步是什么 |

| 各项目的 `交接卡` / `核验报告` | 单个项目的来龙去脉 |

**新 AI 接手的第一句话应该是**："先读 `/workspace/项目档期表.md`（仓库外，进度）和仓库里的 `开工包/START_HERE.md`（总入口），再按 `开工包/docs/04_推仓库交接卡.md` 推仓库。" 你只要把这句发给它就行。

## 二、推仓库的标准四步（任何 AI 照抄即可）

以 `web-sites` 为例，路径 `/workspace/网页仓库_sites`：

```bash
cd /workspace/网页仓库_sites
git status --short                  # 先看清单：确认没有临时文件/缓存混入
git add -A                          # 暂存改动（.gitignore 已挡住 __pycache__/*.pyc/.DS_Store）
git commit -m "这次改了什么"        # 提交，写清楚做了什么
git push origin main                # 推送
git status -sb                      # 确认显示 main...origin/main（无 ahead 才算成功）
```

**国内连 GitHub 经常超时**（`GnuTLS recv error` / `Failed to connect port 443`）——这是网络问题，不是代码问题。**原样重跑 `git push origin main`，通常第 2 次就过**。不要改代码、不要慌。

### 作品集是怎么上线的（推仓库 = 推作品集，没有第二步）

`https://1150986295.github.io/web-sites/` 不是另一个要单独发布的东西，**它就是 `web-sites` 仓库的 GitHub Pages**：

- 仓库根目录的 `index.html` = 作品集门面；`quiz/`、`tpl-b/`、`lanting-assoc/` 等子目录各自成页。
- **发布方式**：push 到 `main` 后，GitHub Pages 自动构建，通常 **1–2 分钟**生效。
- **不需要**：部署命令、FTP、服务器、Vercel、另建仓库、手动点"发布"。
- **确认生效**：打开线上地址强刷（电脑 `Ctrl+F5`，手机下拉刷新）；或比对文件 md5。
- **Pages 有约 10 分钟 CDN 缓存**：刚推完看到的可能还是旧页，加个 `?v=时间戳` 能立刻验证新版。
- **推了却没变**：先看 `git status -sb` 有没有 `ahead`（没推上去），再等 2 分钟，最后才怀疑缓存。

所以"推仓库"和"推作品集"是同一个动作，你只需要会一件事。

### 兜底：完全不靠 git 的发布方式（网页上传）

AI 只给了你整份文件、你手上又没有能跑 git 的环境时，用这个——**不装 git、不用 token、手机也能做**：

1. 手机或电脑浏览器打开 https://github.com/1150986295/web-sites
2. 进到要改的目录（例如 `quiz/`），点右上 **Add file → Upload files**
3. 把改好的 `index.html` 拖进去（同名会覆盖），提交信息写清楚，点 **Commit changes**
4. 等 1–2 分钟，线上自动更新

注意：文件名大小写要和原来一致（`index.html` 不是 `Index.html`），否则会多出一个文件而不是替换。

## 四、三条铁律（写了就是防踩坑）

1. **唯一真相源**：只改仓库内的 `tpl-b/`、`tpl-a/`。`/workspace/模板B_多页应用/`、`/workspace/模板A_单页站/` 是历史快照，**不再同步、不再修改**（2026-11-26 定）。别再比 md5 然后 cp——那是旧流程，只会越同步越乱。
2. **动刀前先读仓库最新版**：别拿本地旧副本覆盖线上版（历史上吃过"本地比仓库旧"的亏）。
3. **改完必验证再推**：JS 语法检查 → 功能实测 → 旧功能巡检回归 → 全绿才推。证据写进文档，不靠口头"完成"。详见 `docs/05_交互增强_第1批搜索筛选.md` 的验收方式。

## 五、token 到期后怎么续（2027-02-23 前处理）

**这一步由你自己在终端做，AI 不参与、也不要它替你做**——因为整个操作要让 token 出现在命令行里。

1. 去 GitHub → Settings → Developer settings → Fine-grained tokens → 生成新的，权限照旧（只开 Contents 读写，授权那 5 个仓库）
2. 你自己在终端执行（把 `<新token>` 换成真值，**别把这条命令粘进任何对话**）。**推荐写进凭据文件，不要写进仓库配置**：
   ```bash
   printf 'https://<用户名>:<新token>@github.com\n' > ~/.git-credentials
   chmod 600 ~/.git-credentials
   git config --global credential.helper store
   # 确认仓库 remote 是干净地址（不带 token）
   git -C /workspace/网页仓库_sites remote set-url origin https://github.com/1150986295/web-sites.git
   ```
3. 推一次验证成功即可（推成功后终端会显示 `main -> main`）。
4. 回 GitHub 把旧 token 删掉（Delete），别留着。
5. 如果换了新环境、`git push` 提示需要认证：**你自己先配好凭据**，再让 AI 只跑 `git push origin main`、`git status -sb` 这类不接触 token 的命令。

> 为什么不让 AI 代做：一旦 token 出现在对话里，它就同时存在于聊天记录、上下文窗口、以及可能被记录的日志里，
> 事后"删掉那条消息"也收不回来。token 泄露 = 那 5 个仓库的写入权限泄露。

## 六、配套工具（外部 AI 产出的代码怎么验收）

如果要验收豆包等其他 AI 做的网页，光会推仓库不够，还要会判断"该不该放"：

- **验收门禁脚本**：`tools/验收门禁.py` —— 跑一下出 15 项 PASS/FAIL，机械判断，不靠主观经验
  ```bash
  python3 tools/验收门禁.py <html文件>            # 站型自动识别
  python3 tools/验收门禁.py <html文件> --kind static   # 手动指定站型
  ```
  门禁按站型分组：**app**（多页应用）查路由表/切场/三态；**static**（单页静态站）查设计令牌/主标题/alt/焦点/触控。
  它只做静态关键词检查，**不代表交互跑通**。
- **站点巡检脚本**：`tools/网页巡检.py` —— 批量跑门禁 + 查站内图片/链接是否真的存在
  ```bash
  python3 tools/网页巡检.py --config tools/巡检配置_全仓库.json --out /tmp/patrol
  ```
- **全流程 SOP**：`docs/03_验收与推仓库流程.md`（本文档的上一份）—— 从收到外部 AI 产出到推仓库五步，换 AI 照做即可

详细流程见那份 SOP，这里不重复。
