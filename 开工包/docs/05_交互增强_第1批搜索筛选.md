> 2026-11-25 完成并推送到 GitHub。这是"把小红书素材变成自己代码"的第一个实例。

## 一、这批做了什么

在模板B的**列表页**加了一个搜索筛选条，三个控件：

| 控件 | 作用 | 对应小红书素材 |
|---|---|---|
| 搜索框（顶部圆角、带放大镜） | 输入关键词，即时筛出标题或正文含该词的条目 | dashboard 组「命令面板」的即时反馈思路 |
| 筛选芯片（全部 / 带图 / 近7天） | 点一下按条件过滤，可和搜索叠加 | dashboard 组「水滴分裂筛选」的多条件切换思路 |
| 命中数提示（"命中 3 条（含「毛」）"） | 让用户知道搜到了多少、搜的是什么 | 通用搜索 ux |

## 二、为什么这样写（三条设计决定）

1. **过滤放在接口层，不放前端**
   改的是 `mock()` 里的 `listItems`，让它接收 `keyword` / `filter` 两个参数。前端只管传参、只认返回结果。
   → 好处：以后接真后端时，把参数发给服务器即可，前端一行不用改。这符合模板B"列表只认接口、不手写死数据"的骨架规矩。

2. **搜索输入做了 250ms 防抖**
   敲一个字等 250ms 再查，不是每敲一下都请求。
   → 好处：数据量大时不卡；这也是所有搜索框的标准做法。

3. **"库空"和"搜不到"是两种空态**
   库里没数据 → 显示"去发布第一条"；搜不到 → 显示"换个词试试"，且不显示发布按钮。
   → 好处：不会让用户把"搜不到"误当成"没内容"。

## 三、改动的四个位置（方便你自己改或让 AI 接手）

| 位置 | 内容 |
|---|---|
| CSS（`.item` 样式前） | `.searchbar` / `.searchbox` / `.filters` / `.chip` / `.hitline`，全用现成令牌，深色模式自动跟随 |
| HTML（`#listWrap` 内首位） | 搜索框 + 三个芯片 + 命中数；空态 span 加了 id 以便切换文案 |
| `mock()` 的 `listItems` | 加 `keyword` 过滤（标题+正文）、`filter` 过滤（image/recent） |
| `LIST` 状态 + 事件 | 状态加 `keyword`/`filter`；输入防抖 + 芯片切换都重置到第一页重拉 |

## 四、验收证据（不是口头"完成"）

- **功能实测 11/11 通过**：初始加载、搜标题、搜正文、命中数、无结果提示、清空恢复、带图筛选、近7天筛选、搜索+筛选叠加、无JS错误红点、桌面端适配保留。
- **旧功能回归 0 FAIL**：阶段2 身份 52 项、阶段3 数据 54 项，共 106 项，与改动前基线数字完全一致——搜索条没碰坏注册/登录/401/403/发布/幂等/备份导入导出。
- 测试时发现一个坑并已确认非 bug：测试注入的假图用残缺 base64 会让浏览器报 404 并累积红点；真实用户场景（无图或正常发图）红点为空。

## 五、怎么复用

这套代码是**通用件**：任何"带列表"的站（作品展示、报名名单、资料库、订单列表）都能整段搬过去。复制时按上面"四个位置"逐块搬即可，样式变量沿用目标站的令牌。
