# 两平台协作流程卡（豆包出代码 + WorkBuddy 落地推送）

> 目的：一个平台的额度/积分用完，换另一个接着干，且流程不依赖某个特定 AI 的记忆。
> 核心分工：**豆包只出代码，不碰仓库；WorkBuddy（任何新对话）负责审核+推送。**

---

## 一、绝对红线：不要把 token 发给豆包

`github_pat_` 开头的 token 授权了你 5 个仓库的写权限。一旦发给外部平台：

- token 会留在对方的对话记录和服务器日志里，**收不回来**；
- 对方 AI 可能把它写进代码注释、贴到别处，无法保证；
- 真出事只能重新生成 token，再把本地 5 个仓库的远程地址全换一遍，很麻烦；
- 而且豆包网页端没有命令行和本地 git，就算给了 token 也很难真正 push——**收益几乎为零，风险极大**。

**结论**：token 只留在 WorkBuddy 这台机器的 git 配置里，任何情况下都不要复制给外部平台。

---

## 二、正确的协作流程

| 步骤 | 谁做 | 做什么 |
|---|---|---|
| 1 | 豆包 | 把某个页面/功能的代码改好，或生成新交互。给它代码时**只发代码片段，不发 token、不发仓库地址** |
| 2 | 你 | 把豆包产出的完整 html **复制发回给 WorkBuddy**（新对话即可） |
| 3 | WorkBuddy | 跑门禁：`python3.11 开工包/tools/验收门禁.py <文件>` |
| 4 | WorkBuddy | 有 FAIL → 按模板骨架重写到全绿；全绿 → 浏览器实测一遍 |
| 5 | WorkBuddy | 推仓库（token 在本机配置里，四步命令见 `04_推仓库交接卡.md`） |
| 6 | 你 | 手机刷新验证 |

---

## 三、新对话怎么启动（关键）

**不是甩 GitHub 链接，而是让它读本机文件**——因为 token 只在本机 git 配置里，纯网页 AI 读到仓库也推不了。

发这句给新对话的 WorkBuddy：

> 先读 `/workspace/网页仓库_sites/开工包/START_HERE.md` 和 `开工包/docs/07_两平台协作流程卡.md`，按里面的状态继续。我随后发一段豆包改好的 html 给你，你负责审核+推送。

（`web-sites` 是公开仓，甩 GitHub 链接给它读也行，但**落地+推送必须在能访问本机的工作环境里做**。）

---

## 四、竞墨的特殊情况（必读）

竞墨是**前后端分离**，跟普通静态站不一样：

- **前端（壳）**：`github.io/web-sites/jingmo/` 和旧地址各有一份，是静态 `index.html`；
- **后端（魂）**：`a1c41f...app.workbuddy.host`（WorkBuddy 服务器），存着 715 题题库、登录、sharecode 鉴权；
- Pages 版代码里把 API 指向那台服务器——**它是靠旧服务器活着的空壳**。

**推论**：

1. 改**前端**（字体/样式/交互）→ push 后 Pages 自动重新部署，几分钟生效，不需要手动"发布"。
2. 改**后端/题库/登录** → Pages 做不到，必须改服务器上那套代码。
3. **旧链接 `a1c41f...app.workbuddy.host` 必须保留**，它是后端本体。用户不用迁移、不用删链接。
4. 想让竞墨**完全属于自己**（不依赖 WorkBuddy 服务器）→ 唯一的路是**买自己的服务器，把后端也搬过去**。在那之前，改前端自由，后端仍在别人机器上。
