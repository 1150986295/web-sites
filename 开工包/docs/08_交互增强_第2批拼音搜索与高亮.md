## 一、能不能当通用？分两层看

| 功能 | 逻辑通用性 | 前提 / 坑 |
|---|---|---|
| 关键词高亮 | ✅ 完全通用 | 函数对任意文本生效，必须走 `esc()` 防注入，否则搜索框输入 `<img onerror>` 会 XSS |
| 拼音搜索 | ⚠️ 半通用 | 搜索逻辑通用，但**每条数据要手动标 `py` 字段**——不是自动转拼音。换数据要重新逐条标，量大易漏 |

**一句话**：能当「通用模式」复用（以后做搜索都照这个结构），但不是「免维护组件」（数据换了 `py` 得重标）。

## 二、拼音搜索的正确做法

### 1）数据层：每条加 `py` 字段
```js
{name:'秘塔写作猫', cat:'writing', keys:'秘塔 写作猫 中文 校对', 
 py:'mita xiezuo mao mtxzm mts', ...}
```
- `py` = 全拼 + 首字母缩写，空格分隔，全部小写
- **谁来标**：出码的 AI 逐条标。数据一多（>30条）建议让 AI 生成时一并产出，别事后手工补
- **验收**：随机抽 2-3 条用拼音首字母搜，能命中才算合格

### 2）匹配层：把 `py` 拼进匹配串
```js
function matches(t){
  var kw = STATE.q.trim().toLowerCase();
  if(STATE.cat !== 'all' && t.cat !== STATE.cat) return false;
  if(!kw) return true;
  return (t.name + ' ' + t.keys + ' ' + (t.py || '')).toLowerCase().indexOf(kw) > -1;
}
```
关键：`(t.py || '')` 兜底，老数据没 `py` 字段也不报错。

## 三、关键词高亮的正确做法

```js
function mark(text){
  var kw = STATE.q.trim();
  if(!kw) return esc(text);
  var i = text.toLowerCase().indexOf(kw.toLowerCase());
  if(i < 0) return esc(text);
  return esc(text.slice(0,i)) + '<mark class="hl">' + esc(text.slice(i, i+kw.length))
    + '</mark>' + esc(text.slice(i+kw.length));
}
```
- **三段都走 `esc()`**，这是防 XSS 的命门——搜索框是用户输入，直接拼进 innerHTML 就会注入
- 用 `<mark class="hl">`，CSS 里给 `.hl` 配色（当前是蓝色底）
- **注意**：拼音命中时显示文本里没有拼音字母，所以高亮不会出现——这是正常的，不是 bug。中文/英文命中才高亮。

CSS：
```css
.card mark.hl{background:rgba(110,140,255,.26); color:var(--ink);
  border-radius:3px; padding:0 2px; box-shadow:inset 0 -1px 0 rgba(110,140,255,.6)}
```

st.textContent = TOOLS.length;                       // 工具数

## 六、复用话术（给豆包/新 AI）

> 在现有搜索功能上叠加两点：
> 1. **拼音搜索**：给每条数据加 `py` 字段（全拼+首字母缩写，空格分隔小写），匹配时把 `py` 拼进匹配串，用 `(t.py||'')` 兜底。
> 2. **关键词高亮**：加 `mark(text)` 函数，命中词用 `<mark class="hl">` 包裹，**三段文本都要 `esc()` 转义防 XSS**。
> 3. 头部统计改为从数据自动计算，不写死。
> 完成后自测：中文/拼音/首字母命中、高亮、XSS 注入、空态、统计一致。
