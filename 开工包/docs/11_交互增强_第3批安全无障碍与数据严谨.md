# 交互增强 第3批：安全、无障碍与数据严谨（V7 实战沉淀）

> 来源：`ai-tools-nav` V7（2026-11-26）。豆包/新对话在 V6 基础上提出 10 条意见（9 项改动 + 1 项明确不改），主对话逐条实测后确认全部属实并上线。
> 这一批的价值不在"功能更多"，而在**看不见的健壮性**：安全、无障碍、数据可信。做展示站时最容易漏，恰恰是接单时最显专业的地方。
> 铁律照旧：**外审意见一律实测再判，不照单全收**（见 docs/09）。这 10 条我全部亲手复现/反证过：9 条改了，1 条（第 10 行）判定"认表述、不动代码"。

## 一、10 条逐条判定（9 改 + 1 不改，全部 A 类属实）

| # | 改进点 | 为什么之前没注意到 | 我的实测验证 | 判定 |
|---|---|---|---|---|
| 1 | **safeUrl 协议白名单** | 数据都是 https 硬编码，没人想过数据会被改成 `javascript:` | 用 route 把一条 url 改成 `javascript:alert(1)//`，渲染后危险 href 数 = 0（退化为 `#`） | ✅ A 必改 |
| 2 | **整卡语义链接**：正文包进 `<a>`，星标按钮放 `<a>` 外 | 旧版是空 `<a>` 盖住卡片（`position:absolute;inset:0`），屏幕阅读器读不到标题/简介 | DOM 检查 40/40 卡：h3/p 都在 a 内、星标在 a 外；点星标收藏正常且不误跳转 | ✅ A 必改 |
| 3 | **焦点保护**：重建 DOM 前记住焦点，重建后按 data 属性恢复 | 搜索/筛选会全量 `innerHTML` 替换，键盘用户的焦点被清空、要重新 Tab | 聚焦"Notion AI"星标→搜它自己→焦点仍是该星标（BUTTON） | ✅ A 必改 |
| 4 | **触控目标 ≥44px** | chip 38px、sw 34px，看着没问题，但低于 WCAG 44px 建议 | computed minHeight chip/sw 均 = 44px | ✅ A 必改 |
| 5 | **desc 入搜索匹配串** | 只拼了 name/keys/py/task/why，漏了 desc，用户搜简介里的话搜不到 | 搜"参数与风格全在手"（只在 desc 里）→ 命中 1 | ✅ A 必改 |
| 6 | **红点面板重新读取 localStorage** | 闭包捕获了创建时的旧 `a` 数组，新错误加进来后打开面板看不到 | 注入两条新错误后开面板 → 两条都显示 | ✅ A 真 bug |
| 7 | **深色底阴影改亮色微光** | 阴影颜色是 `rgba(0,0,0,.18)`，深色底上物理不可见，等于没阴影 | 截图确认卡片在近黑背景有层次；公式仍守 X=0、模糊>偏移、扩散为负 | ✅ A 属实 |
| 8 | **3 个失效 URL 修正** | 通义千问/文心/腾讯会议官网改版，旧链接跳错页 | 全部改为现行地址（通义→`tongyi.aliyun.com/qianwen/`、文心→`yiyan.baidu.com`、腾讯会议→`meeting.tencent.com/ai/`），40 条 URL 全 https | ✅ A 属实 |
| 9 | **4 处精确数字改"有免费额度"** | 即梦60积分/万相50灵感值/可灵66灵感值/Copilot15次——这类额度数字会变，写死就过期误导 | 全文残留"每日约" 0 处 | ✅ A 属实 |
| 10 | **未改 2 条（如实说明）** | 测评说 stability.ai / wenku.baidu.com "粒度过粗"，但前者是 SD 官方项目站、后者 AI 集成在文库内无独立域名 | 未换第三方链接——换了风险更大。`stability.ai`、`wenku.baidu.com` 保留 | ✅ **D 类：认表述、不动代码** |

另：触控目标移动端从 4 列 grid 改回 flex-wrap（40 工具 + 6 芯片挤不下）、动画延迟 `min(i,8)` 封顶（1.8s→360ms，40 卡不用干等）、`pinch-zoom` 恢复（WCAG 要求，原 `pan-y` 禁了双指缩放）、徽标字号 12px→移动端 13px、`chip.view` 给收藏/最近加 1px 竖线分隔（个人视图与内容分类视觉分层）、`goto()` 删死代码 `if(STATE.cat===cat && opts.instant) syncChips()`——这些都是细节，一并吸收。

> **重点看第 10 项**：这才是"外审意见不照单全收"的正面示范。测评说"粒度过粗"是**表述**层面的意见，但换成第三方链接会引入风险（失效/非官方/不可控）。**判断标准是"改了是否更好"，不是"意见是否说中"**——说中了也可以不改，只要如实说明为什么。新对话这次主动列出"未改 2 条 + 理由"，比闷头全改更专业，这正是 docs/09 判断台账要培养的能力。

## 二、可复用代码（做任何卡片列表站都该带上）

### 1. URL 协议白名单（纵深防御）

```js
/* URL 协议白名单：纵深防御——即使数据被改成 javascript: 也不会执行 */
function safeUrl(u){
  var s = String(u || '').trim();
  return /^https?:\/\/\S+$/i.test(s) ? s : '#';
}
// 卡片链接：href 用 safeUrl(t.url)，不要直接 esc(t.url)
```

> 作用：`esc()` 只能防 HTML 注入，挡不住 `href="javascript:..."`。`safeUrl` 补上协议层。

### 2. 整卡语义链接 + 星标外置

```html
<!-- 结构：卡片 div > [星标 button] + [a.card-hit 包住全部正文] -->
<div class="card">
  <button class="star" data-fav="..." aria-pressed="false">★</button>
  <a class="card-hit" href="https://..." target="_blank" rel="noopener noreferrer" data-rec="...">
    <div class="card-top">...图标/分类...</div>
    <h3>标题</h3><p>简介</p>
    <div class="meta">...徽标...</div>
    <span class="visit">访问官网（新窗口）↗</span>
  </a>
</div>
```
```css
.card-hit{display:flex; flex-direction:column; gap:var(--sp-2); flex:1; min-width:0;
  text-decoration:none; color:inherit; cursor:pointer; border-radius:var(--r-l)}
.card-hit:focus-visible{outline:2px solid var(--accent); outline-offset:2px}
```
> 要点：**交互元素不能嵌套**（`<button>` 不能放进 `<a>`）。星标是独立按钮，放 `<a>` 外；正文全进 `<a>`，屏幕阅读器 Tab 时能连续读到标题/简介/徽标。

### 3. 焦点保护（列表全量重建时）

```js
function render(animate){

  var ae = document.activeElement, focusSel = null;
  if(ae && grid.contains(ae)){

    if(f) focusSel = '.star[data-fav="' + f + '"]';
    else if(r) focusSel = '.card-hit[data-rec="' + r + '"]';
  }
  grid.innerHTML = list.map(cardHTML).join('');
  ...
  if(focusSel){ var fe = grid.querySelector(focusSel); if(fe) fe.focus(); }
}
```
> 边界：焦点的卡被筛掉时 `querySelector` 返回 null，安全跳过，不报错——这是正确降级。

### 4. 搜索匹配串要拼全字段

```js
return (t.name + ' ' + t.keys + ' ' + (t.py || '') + ' ' + (t.task || '')
     + ' ' + (t.why || '') + ' ' + t.desc).toLowerCase().indexOf(kw) > -1;
```
> 新增字段时记得同步这里，否则"页面上写了却搜不到"。

### 6. 深色底阴影改亮色微光

```css
/* 深色底用黑阴影物理上不可见。改用低透明度亮色微光，
   仍守 X=0、模糊>偏移、扩散为负 */
```

## 三、验收清单（在本批基础上追加）

给新对话/任意 AI 做卡片列表站时，除 15 项门禁外，逐条打勾：

- [ ] 40 条（或全部）URL 全 https；把一条改成 `javascript:` 测试，`href` 退化为 `#`
- [ ] 每张卡：正文在 `<a>` 内、星标/其他按钮在 `<a>` 外；点按钮不误跳转
- [ ] 搜索/筛选后焦点能恢复；焦点的卡被筛掉不报错
- [ ] chip / 开关 / 按钮 computed `min-height ≥ 44px`
- [ ] 搜一个只出现在 desc 里的词，能命中
- [ ] 连续注入两条错误后打开红点面板，两条都显示
- [ ] 深色主题阴影肉眼可见（亮色微光），浅色主题黑阴影正常
- [ ] 无 `pointer-events` 把卡片点区挡住；`pinch-zoom` 未被禁用（`touch-action:pan-y pinch-zoom`）
- [ ] 额度/价格类数字不写死（会过期）：用"有免费额度"等稳定表述，全文搜"每日约"应为 0
- [ ] 外审意见逐条给判定，**包括不改的**：每条要么改、要么写清为什么不改（见 docs/09 四类法）

## 五、V7 做法同步进通用模板的记录（2026-11-26）

V7 的 10 项做法不是全都能进模板——**按"有调用点才加"筛选，避免塞死代码**。同步结果：

| 做法 | 模板A（纯静态单页） | 模板B（多页应用） | 原因 |
|---|---|---|---|
| `pinch-zoom` | ✅ 已加 | ✅ 已加 | V8 起两模板均为 `touch-action:pan-y pinch-zoom`；早期只写 `pan-y` 把双指缩放一起禁了 |
| 红点面板重读 | ✅ 已加 | ✅ 已加 | 两模板红点都有闭包旧列表 bug，是真 bug 必修 |
| `focus-visible` 焦点环 | ✅ 已加 | 上次已补 | 无障碍底线 |
| 44px 触控目标 | ✅ 无需额外处理 | ✅ chip/tab 已加 | 模板A 只有主操作按钮，本身 ≥44px；模板B 有 chip/tab，已补到 44px（门禁 static 组会查这条） |
| `safeUrl` 协议白名单 | ❌ 不加 | ❌ 不加 | 两模板**无用户可控外链**：A 纯静态无链接，B 只有自家 `createObjectURL` 下载。没调用点=死代码 |
| 焦点保护 | ❌ 不加 | ❌ 不加 | 模板B 列表是 `appendChild` 增量渲染，不是全量 `innerHTML` 重建，焦点不会被清空；导航站才需要 |
| desc 入搜索 | ❌ 不加 | ❌ 不加 | 模板A 无搜索；模板B 列表按 `title/body` 过滤，无 `desc` 字段概念 |
| 整卡语义链接 | ❌ 不加 | ❌ 不加 | 两模板无"卡片跳官网"结构，是导航站专属 |
| 亮色微光阴影 | ❌ 不加 | ❌ 不加 | 两模板是宣纸浅色主题，黑阴影正常；深色主题才需要微光 |
| URL/额度数据修正 | ❌ 不加 | ❌ 不加 | 属具体数据，非骨架；数据严谨原则已写进验收清单 |

**验证**：门禁按站型分组后，模板A、模板B **均 15/15**（2026-11-26 门禁升级前模板A 只能 12/15，是把应用站标准套到静态页的误判，已修，别再当成"设计如此"）；浏览器实测 **16/16**（pinch-zoom/焦点环/红点重读/44px/四断点无溢出/无 JS 异常）。

> 结论：**底线项（安全/无障碍/真 bug）进模板，场景项留在 docs 按需取**。以后 V7 再有新做法，照这个筛选逻辑判断，不要一股脑塞进骨架。
