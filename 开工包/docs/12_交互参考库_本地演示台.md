# 12 · 交互参考库 → 本地演示台（把"看文字"变成"动手试"）

> 触发场景：你已经有一份"交互效果参考库"（列表 + 文字要点 + 外站链接），但用户点开卡片只看到文字，想看真效果还得跳别人的网站。本文记录把它改成**卡片内可跑演示**的做法与验收方式。

---

## 1. 为什么不能只给文档

用户的原话是"点一个卡片还得跳另一个网页看详情"。这说明参考库的价值漏了一半：

| 只给文字 | 给演示 |
|---|---|
| 读者要自己在脑内还原动效 | 一眼看到节奏、缓动、幅度 |
| 外链会失效、要联网、有第三方风险 | 本地跑，断网可用 |
| 无法判断"这个效果适不适合我的页面" | 直接对比取舍 |

**结论**：参考库应该是"可操作的样板间"，文档只是配套说明。外链降级为「参考来源」，不是主入口。

---

## 2. 结构：一个演示台 + 每项一段定义

> 本文记录的是建台时的原始 86 项；2026-11-28 已补第 87 项「数据导出与导入」（`ix_backup`），做法与下面完全一致，不另起结构。

不要为 86 项写 86 个页面。用**一个挂载器 + 一张映射表**：

```js
var DEMOS = (function(){
  var D = {};
  function reg(slug, o){ D[slug] = o; }   // {hint, html, run}
  reg('ripple',{
    hint:'点框内任意位置',
    html:'<div class="dm-ripple">点这里，看涟漪</div>',
    run:function(stage){ /* 只操作 stage 内部 */ }
  });
  return D;
})();

function mountDemo(slug, host){
  var d = DEMOS[slug];
  host.innerHTML = '<div class="dm">'+(d.hint?'<div class="dm-hint">'+esc(d.hint)+'</div>':'')+
                   '<div class="dm-stage"></div></div>';
  var stage = host.querySelector('.dm-stage');
  stage.innerHTML = d.html;
  try{ d.run && d.run(stage, host); }
  catch(e){ stage.innerHTML = '<div class="dm-empty">演示初始化失败</div>'; }
}
```

三个字段就是全部契约：`hint`（怎么操作）、`html`（初始 DOM）、`run`（绑定交互）。新增一项只需 `reg()` 一次。

**懒挂载**：卡片展开时才 mount，并用 `data-on` 标记防重复；收起不销毁（保留状态），列表重建时自然回收。

---

## 3. 五条硬约束（踩过才知道）

1. **零外部依赖**：不引 CDN、不引图标库、不用外链图片。演示用 CSS 渐变 + 内联 SVG + canvas 画。断网必须能跑。
2. **定时器必须自停**：所有 `setInterval` / `requestAnimationFrame` 循环首行加 `if(!el.isConnected){ clearInterval(t); return; }`。否则列表重建后旧循环还在跑，几十个叠加会卡死页面。
3. **文本一律 `esc()`**：动态拼 HTML 时转义。参考库原版速查页用 `innerHTML` 直拼、没转义，这是隐患，不要照搬。
4. **canvas 按 DPR 适配**：`cv.width = rect.width * devicePixelRatio`，再 `ctx.setTransform(dpr,0,0,dpr,0,0)`，否则高分屏发虚、坐标偏移。
5. **尊重动效开关**：`.no-motion *` 与 `prefers-reduced-motion` 已在全局关掉 animation/transition，演示会自动静止——这是正确行为，不要给演示开例外。

---

## 4. 演示台的版式要点

- 演示区是**卡片内的一个区块**，不是全屏：`border:1px dashed` 或浅底 + 圆角，`min-height` 约 120–140px，`padding:16px`。
- **宽屏要限宽**：参考库正文 `max-width:820px` 居中，演示区 `max-width:560px` 居中。否则在 1000px+ 屏上演示会被拉成扁长条，长句也不好读。
- 提示行（`hint`）用小圆点 + 11px 灰字，放在演示区上方，告诉用户"怎么玩"；否则用户会以为是个静态图。
- 演示区里**不要放文字和控件抢中心位置**：如指针类演示，光点居中就把说明文字挪到底部，避免重叠。

## 5. 验收：不能靠"看起来没问题"

86 个演示手写必然有错，必须机械验证。三轮，都用无头 Chromium + 注入自测脚本、结果写进 `document.title` 再 `--dump-dom` 读出（比 CDP 稳，不会因浏览器进程回收而静默失败）。

### 第 1 轮：覆盖率 + 能否挂载

```js
refs.forEach(function(x){
  var host = document.createElement('div');
  document.body.appendChild(host);
  try{ window.mountDemo(x.slug, host); }catch(e){ fail.push(x.slug); }
  var st = host.querySelector('.dm-stage');
  if(!st || st.textContent.indexOf('演示初始化失败')>=0) fail.push(x.slug);
  if(st && st.textContent.indexOf('暂无本地演示')>=0) noDemo.push(x.slug);
  host.remove();
});
```
判据：`total === ok`，`noDemo / fail` 为空。

### 第 2 轮：交互行为断言

不测"有没有元素"，测"操作后状态变没变"：

| 类型 | 断言 |
|---|---|
| 涟漪 | dispatch pointerdown 后 `.dm-rip` 数量 > 0 |
| 点赞 | 点击后数字 128→129，粒子节点 > 0 |
| 搜索 | 输入关键词后可见行数 = 预期；输入乱码后空态显示 |
| 验证码 | 填满 6 位后提示含"通过" |
| 拖拽排序 | 首项拖到末位后，末位文本 = 原首项 |
| 键盘 | dispatch ArrowRight 后方块 transform 含 translate，且显示按键名 |
| 上传/任务 | 等待后进度或状态文案变化 |
| 浮层 | 打开后 `.on`，Esc 后移除 |

### 第 3 轮：布局体检（86 张全挂一遍）

```
stage.scrollWidth > stage.clientWidth + 2   → 横向溢出
canvas.width === 0                          → 零尺寸画布（挂载时容器还不可见）
stage.height < 60                           → 演示区塌陷
```

## 6. 一个真实的坑：`requestAnimationFrame` 计数

数字滚动最初用 rAF + `performance.now()`。无头虚拟时钟下 rAF 只走了 1 帧，测出 `584`（目标 12800）。看似测试假象，但它同时暴露了真问题：**后台标签页 rAF 会被节流甚至暂停**，用户切回来才继续。

改为 `setInterval(...,16)` + `Date.now()` 计算进度：后台仍能推进，且可被虚拟时钟验证。

> 经验：凡是"必须走完"的进度类动画，用 `setInterval`；纯装饰性的连续动画才用 rAF。
