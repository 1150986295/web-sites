# 工具说明 · 验收门禁 与 网页巡检

两个脚本都只解决一件事：**把"这份 HTML 能不能进仓库"变成同一条命令、同一个结论**，换人、换 AI、换会话都不变。

## 环境

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | **3.8+**（实测 3.11） | 只用标准库，**不需要 pip install**，不需要虚拟环境、不需要联网 |
| Node.js | 可选 | 只有门禁的「JS 语法无错误」一项要用它；没装 node 时这一项 FAIL，并提示"装好再跑"，不是代码坏了 |
| 系统 | Windows / macOS / Linux | 无系统相关代码，路径分隔符自动处理 |

**Windows 两处差异**：

1. 命令里的 `python3` 换成 `python`（或 `py`）；本机若 `python` 指向 Python 2，用 `py -3`。
2. 路径含空格要加引号；控制台中文乱码先 `chcp 65001`。

**所有命令都在仓库根目录执行**（`web-sites/` 这一层）。脚本按自身位置推算仓库根，页面路径一律写"相对仓库根"的形式（如 `tpl-b/index.html`），不要 `cd` 进 `开工包/` 再跑。

## 一、验收门禁.py —— 单页体检

```bash
# 最常用：跑一份页面
python3 开工包/tools/验收门禁.py tpl-b/index.html

# 强制指定站型（自动识别不准时用）
python3 开工包/tools/验收门禁.py index.html --kind static

# 给机器读（CI、别的脚本）
python3 开工包/tools/验收门禁.py quiz/index.html --json
```

| 参数 | 作用 |
| --- | --- |
| `<html文件路径>` | 必填，相对仓库根或绝对路径都行 |
| `--kind static\|app` | 强制站型；不写则自动识别（有 `ROUTES` / 切场引擎特征 → app，否则 static） |
| `--json` | 输出 JSON 报告，不打印人读版 |

**退出码**：`0` = 格式项全过（GREEN）／`1` = 有 FAIL 需处理（RED）／`2` = 用法或文件错误（脚本本身的问题）。

**15 项怎么来的**：通用 10 项（有效内容非空壳、DOCTYPE、viewport、`lang="zh-CN"`、有 JS、JS 语法、无水印、无外链、无动态代码执行、无硬编码密钥）+ 骨架 5 项，按站型分组：

- `app`（多页应用）：路由表 `ROUTES`、切场引擎、三态（加载/空/错误）、错误红点、设计令牌 `:root`
- `static`（单页静态站）：主标题 `h1`、键盘焦点可见、触控目标 44px、图片 `alt`、设计令牌 `:root`

几项容易误解的判定：

| 项 | 怎么判 | 说明 |
| --- | --- | --- |
| 有效内容(非空壳) | 文件 >500 字符 **且可见文字 ≥50 字** | 去掉 `<script>/<style>/<标签>` 后的正文；空壳能堆关键字，堆不出正文 |
| 主标题 `h1` | 必须 ≥1；**多于 1 个记 WARN** | 0 个是空壳/结构缺失的强信号，直接 FAIL；`ziliao-tpl` 现有 22 个 h1，属待收敛的已知债 |
| 无动态代码执行 | `eval(` / `Function(` / `constructor.constructor` / `setTimeout("…")` / `setInterval("…")` | 后三类不出现 `eval` 字样，旧版正则会漏 |
| 触控目标 44px | 有交互才查；未声明 `44px`/`--tap` 直接 FAIL | 声明了仍会用静态规则扫按钮类选择器里的 `<40px` 固定尺寸，只报 WARN（`calc`/继承会漏，必须浏览器实测） |

**能力边界（必须如实转述）**：只做静态关键词与结构检查，**不代表功能可用**。它能挡住"忘了写 viewport""空壳堆关键词""constructor.constructor 逃逸"这类结构性错误，但**不点按钮、不量真实尺寸、不做安全审计**。15/15 之后仍要浏览器实测关键交互。

> `jingmo/index.html` 长期 **13/15 RED**，属预期：它是前端快照，后端已剥离。**不要为了让它变绿去补 ROUTES/切场/三态**。

## 二、网页巡检.py —— 一批页面批量巡检

在门禁之上多查两件事：页面引用的图片/CSS/JS/站内链接**文件在不在**，以及上线后 URL **是不是真的 200**。

```bash
# 按配置巡检一批（最常用：自动扫全仓库，当前 11 个页面）
python3 开工包/tools/网页巡检.py --config 开工包/tools/巡检配置_全仓库.json --out /tmp/patrol

# 不写配置，扫仓库里所有 index.html
python3 开工包/tools/网页巡检.py --all --out /tmp/patrol

# 叠一层线上检查：先把站点跑起来（python3 -m http.server 8000），再给 --base-url
python3 开工包/tools/网页巡检.py --config 开工包/tools/巡检配置_全仓库.json --out /tmp/patrol \
    --base-url http://127.0.0.1:8000
```

| 参数 | 作用 |
| --- | --- |
| `--config <json>` | 巡检配置；与 `--all` 二选一 |
| `--all` | 扫仓库内所有 `index.html`（跳过 `images/`、`node_modules/`、点开头目录） |
| `--out <目录>` | 报告输出目录，默认 `/tmp/patrol`；产出 `patrol.json` + `patrol.md` |
| `--base-url <URL>` | 可选，追加 HTTP 状态检查；配置里也可写 `base_url`，命令行优先 |

**退出码**：`0` = 全部通过／`1` = 有 FAIL／`2` = 用法或配置错误。

配置格式（路径相对仓库根）：

```json
{
  "name": "全仓库页面巡检",
  "files": [],
  "discover": {
    "include": ["**/index.html"],
    "exclude": ["开工包/**", "screenshots/**"]
  },
  "known_fail": {
    "jingmo/index.html": "前端快照：后端已剥离，接口 404 属设计"
  },
  "base_url": "http://127.0.0.1:8000"
}
```

- `files`：手写清单，可留空；`discover` 会把 glob 命中的页面并进来，**新增页面不会再漏**
- `known_fail`：登记在案的已知问题页。**仍然会跑、仍然打印失败项**，只是不计入"意外失败"和退出码；结论行会写"另有 N 个已登记问题页"，不会假装全绿

**能力边界**：静态层是文本分析，证明不了"交互跑通"；线上层只证明"能取到"，证明不了"长得对"。首屏视觉与交互仍要人眼/浏览器过一遍。

## 三、什么时候用哪个

| 场景 | 用 |
| --- | --- |
| 外部 AI 交来一份新页面，判断能不能收 | 验收门禁（单份） |
| 改完仓库要提交，确认没把别的页面改坏 | 网页巡检 `--config 巡检配置_全仓库.json` |
| 部署后确认没裂图、没死链 | 网页巡检 + `--base-url` |
| 只想看某一项为什么 FAIL | 验收门禁，看逐项 PASS/FAIL 那几行 |

> 顺序上，**先把门禁本身补可信，再上 CI**——门禁能被空壳骗过时，CI 只是把不可信的绿灯自动化。
